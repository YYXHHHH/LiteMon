## 0. 文档说明

### 0.1 要解决什么

面板现在**可以被拖到任意位置**，但拖动是无条件生效的：用户把面板摆到顺手的位置后，只要不小心按住标题区拖一下、或拖动时手抖，位置就变了。

本功能在面板右上角加一个**图钉按钮**：

- 点一下 → 面板**钉死在当前屏幕位置**，此后任何拖拽都不再移动它；
- 再点一下 → 解锁，恢复可拖动；
- 固定状态与位置**持久化**，重启后仍钉在原处；
- 解锁后可以重新摆位，摆好再点图钉，位置同样被记住。

### 0.2 不做什么

- ❌ 不做"边缘吸附/磁吸对齐"（后续可加）
- ❌ 不做"锁定后点击穿透"（那会让面板无法再点图钉，属于自锁）
- ❌ 不做多屏之间的自动迁移（只做越界回收到可见区域）
- ❌ 不做全局快捷键

### 0.3 编号约定

沿用上一份文档：`FR-xx` 功能需求、`NFR-xx` 非功能、`D-xx` 决策、`TC-xx` 手工用例、`RI-xx` 单元测试、`R-xx` 风险。

## 1. 需求

### 1.1 用户故事

| 编号 | 作为 | 我想要 | 以便 |
|---|---|---|---|
| US-1 | 长期挂机用户 | 把面板摆到副屏角落钉住 | 不挡主屏、也不会被误拖走 |

| US-3 | 普通用户 | 重启后还在原处 | 不用每次重新摆 |

### 1.2 功能需求

| 编号 | 需求 | 验收口径 |
|---|---|---|
| FR-01 | 面板右上角有图钉按钮 | 关闭按钮左侧、同一行，4 DIP 间距 |
| FR-02 | 点击图钉切换固定/解锁 | 单次点击切换，无延迟 |
| FR-03 | 固定时拖动无效 | 按住面板任意位置拖动，窗口不移动 |
| FR-04 | 固定时有明确视觉反馈 | 图标变为强调色实心 + 面板边框变为强调色 40% |

| 编号 | 需求 | 度量 |
|---|---|---|
| NFR-01 | 点击到状态变化 ≤ 1 帧 | 目测无延迟；无异步 |
| NFR-02 | 拖动保存不产生频繁磁盘写 | 仅在拖动结束写一次 |
| NFR-03 | 不增加常驻内存 | 新增字段为几个 double/bool |

> 点图钉 → 怎么拖都不动；再点 → 又能拖；重启后还在原位，且换分辨率不会跑到屏幕外。

## 2. 现状分析

### 2.1 头部绘制与命中区

`src/LiteMon.App/PanelView.cs`（自绘面板，`OnRender`）：

```csharp
// 第 216–219 行（现状）
dc.DrawText(GetText("LiteMon", 15, true, ValueBrush), new Point(16, 11));
dc.DrawText(GetText(_headerText, 10, false, MutedBrush, width - 88 - 40), new Point(88, 16));
dc.DrawLine(ClosePen, new Point(width - 28, 15), new Point(width - 18, 25));
dc.DrawLine(ClosePen, new Point(width - 18, 15), new Point(width - 28, 25));
```

关闭按钮是**画出来的两条线**（不是 WPF Button），命中测试在 `PanelWindow` 里用坐标判断：

```csharp
// src/LiteMon.App/PanelWindow.cs:159-181（现状）
private void OnMouseLeftButtonDown(object sender, MouseButtonEventArgs e)
{
    if (e.ChangedButton != MouseButton.Left) return;

    Point position = e.GetPosition(this);
    if (position.X > Width - 44 && position.Y < 40)   // 右上角 44×40 是关闭区
    {
        Close();
        return;
    }

    try { DragMove(); }                                // 其余区域一律拖动
    catch (InvalidOperationException) { }
}
```

结论：

1. 头部**没有任何"按钮"控件**，全部是绘制 + 坐标判断，所以图钉也要照这个模式做；
2. 命中区判断是"关闭区 44 宽"，新增图钉需要把右上角切成两个区；
3. `DragMove()` 是唯一移动窗口的入口，**锁定的落点就是它**（固定时直接 return 即可）。

### 2.2 窗口属性

`PanelWindow` 构造里：

| 属性 | 值 | 对固定功能的影响 |
|---|---|---|
| `Topmost` | `true` | 已经永远置顶，固定**不需要**再改置顶（用户说的"悬浮"已满足） |
| `WindowStyle` | `None` | 无系统标题栏，拖动完全由我们的坐标逻辑控制 |
| `ResizeMode` | `NoResize` | 尺寸固定 340×560，无法被拉大 |
| `ShowInTaskbar` | `false` | 任务栏无入口，误关后只能重开 |
| `Left/Top` | 构造时算右上角 | 目前**不持久化**，每次启动回到默认位置 |

### 2.3 设置层现状（上一功能已建好）

`src/LiteMon.Settings/AppSettings.cs` 现在只有：

```csharp
public int Version { get; init; } = 1;
public double RefreshIntervalSeconds { get; init; } = 1;
public TimeSpan Interval => …;        // [JsonIgnore]
```

`SettingsStore` 的读写、原子替换、损坏隔离、路径回退都已具备，**本功能只需要加字段**，不需要动存储层。

### 2.4 三条约束

1. **Core 不能引用 WPF**：位置计算要放进 Core 就必须用纯 `double` 参数，不能出现 `System.Windows.Rect`（`Rect` 在 WindowsBase 里）。
2. **拖动期间不能写盘**：`DragMove()` 是阻塞调用，返回时鼠标已松开 —— 这是唯一合适的保存时机。
3. **越界必须自愈**：用户可能把窗口存在副屏坐标（负坐标），拔掉副屏后 `Left = -2000` 会让窗口彻底不可见，必须在启动时收敛。

## 3. 方案设计

### 3.1 状态机

```
        ┌──────────────┐   点击图钉     ┌──────────────┐
        │   未固定      │ ───────────▶ │    已固定     │
        │  可拖动       │ ◀─────────── │  拖动无效     │
        │  灰描边图钉    │   点击图钉     │  强调色图钉   │
        └──────────────┘                │  强调色边框   │
              │ 拖动结束                 └──────────────┘
              ▼                                │ 拖动被忽略
        保存 Left/Top                          ▼
                                          位置不变
```

### 3.2 关键决策

| 编号 | 决策 | 备选 | 理由 |
|---|---|---|---|
| **D-01** | 图钉放在**关闭按钮左侧**，命中区宽 28 DIP | 放左侧标题、放右键菜单 | 右上角是"窗口控制区"的肌肉记忆；右键菜单已有 3 项，再加会拥挤 |
| **D-02** | 命中区按 `y < 40` 与关闭区**同级**，互不重叠 | 用 WPF Button 叠在上面 | 现有面板全自绘，引入 Button 会破坏"一个 FrameworkElement 画所有东西"的结构，还要处理透明背景命中 |
| **D-03** | 固定 = **禁用 `DragMove()`**，不改窗口样式 | 用 `WindowChrome` 锁、改 `ResizeMode`、禁用 HitTest | `WindowStyle=None` 下唯一移动路径就是 `DragMove`；改样式会引入闪烁与 DPI 重算 |
| **D-04** | 固定状态 + 位置都持久化 | 只持久化状态 / 只持久化位置 | 用户的完整意图是"钉在这个位置"，缺一不可 |
| **D-05** | 位置用**虚拟屏幕**边界收敛（支持负坐标） | 用主屏 / 用当前屏 | `SystemParameters.VirtualScreen*` 覆盖所有显示器，副屏在左（负坐标）也正确 |
| **D-06** | 固定时也保留 `Topmost`，不做"点击穿透" | 锁定时穿透鼠标 | 穿透后就点不到图钉，用户会被锁死 |
| **D-07** | 视觉反馈用"图标强调色 + 边框强调色 40%" | 弹 Toast / 改标题 | 无打扰、零额外窗口；边框变化让"锁住了"一眼可见 |

### 3.3 命中区几何（DIP）

窗口宽 340，头部高 40：

```
0                                                          340
├──────────────────────────────────┬──────┬──────────────────┤
│  标题 "LiteMon 每 N 秒刷新"        │ 📌   │        ×         │
│                                  │ 28   │       44         │
└──────────────────────────────────┴──────┴──────────────────┘
                                     ▲      ▲
                              width-72   width-44
```

| 区域 | X 范围 | Y 范围 | 行为 |
|---|---|---|---|
| 关闭 | `X > Width - 44` | `Y < 40` | `Close()` |
| 图钉 | `Width - 72 < X ≤ Width - 44` | `Y < 40` | 切换固定 |
| 其它 | — | — | 未固定时拖动，固定时忽略 |

> 判定顺序：**先关闭，后图钉**，避免边界值（正好在 `Width-44`）时误触。

### 3.4 一次切换的完整链路

```
点击图钉
 1. PanelWindow.OnMouseLeftButtonDown 命中图钉区
 2. TogglePin(): _isPinned = !_isPinned
 3. _view.SetPinned(_isPinned)  → 重绘图标与边框
 4. _onPinnedChanged(_isPinned) → App 写 _settings.IsPinned
 5. App: SettingsStore.TrySave(...)（失败静默）
 6. 后续左键按下：若 _isPinned 直接 return（不调 DragMove）
```

### 3.5 移动与保存时机

```
未固定状态按下左键（非按钮区）
 1. 记录 _dragOriginLeft/_dragOriginTop
 2. DragMove()             ← 阻塞，直到松开鼠标
 3. 返回后比较 Left/Top，变化则 _onMoved(Left, Top)
 4. App 写入 WindowLeft / WindowTop 并 TrySave
```

保存的是 **DIP**（WPF 逻辑像素），不是物理像素。原因：

- 面板已经是 PerMonitorV2，换 DPI 时 WPF 自动换算；
- 若存物理像素，125% ↔ 150% 切换后位置会漂移。

### 3.6 启动时位置收敛

```
settings.WindowLeft/WindowTop 存在？
   ├─ 是 → 与虚拟屏幕求交，必要时推回可见区域
   └─ 否 → 默认：Right - 340 - 24, Top + 24
```

`WindowPlacement.Clamp` 规则（见 5.1）：

1. 入参为 `null` 或非有限值 → 用默认锚点；
2. 位置超出虚拟屏幕 → 夹到边界内；
3. 窗口比屏幕还大（极端分辨率）→ 对齐屏幕左上角。

## 4. 数据与配置

### 4.1 新增字段

```csharp
public bool IsPinned { get; init; }          // 默认 false
public double? WindowLeft { get; init; }     // 默认 null = 用默认位置
public double? WindowTop { get; init; }
```

- 用 `double?` 而不是 `double` + 哨兵值：`null` 明确表达"没保存过"，避免 `0,0` 与"左上角"混淆；
- **不升 `Version`**：新增字段带默认值，旧配置反序列化后自动为 `false/null`；新配置被旧版本读到时，未知字段被忽略（`System.Text.Json` 默认行为）。

### 4.2 配置文件示例

```json
{
  "version": 1,
  "refreshIntervalSeconds": 1,
  "isPinned": true,
  "windowLeft": 2100,
  "windowTop": 60
}
```

### 4.3 兼容矩阵

| 场景 | 结果 |
|---|---|
| 旧版配置（无新字段） | 未固定、默认位置 |
| 新版配置被旧版读取 | 旧版忽略三个新字段，刷新间隔仍生效 |
| `windowLeft` 为字符串/对象 | 反序列化异常 → 整体回默认 + 隔离为 `.bad`（沿用既有策略） |
| `windowLeft = 99999` | 启动时夹回屏幕内 |
| `windowLeft = null` 但 `windowTop` 有值 | 两者都视为缺失，用默认位置（保持一致） |

### 5.1 新增 `src/LiteMon.Core/Layout/WindowPlacement.cs`

放进 Core 是为了**能用纯逻辑测试**（Core 不引用 WPF，测试不需要起窗口）。

```csharp
namespace LiteMon.Core.Layout;

/// <summary>
/// 窗口位置计算（纯函数，不依赖 WPF）。
/// 负责把"上次保存的位置"收敛到当前虚拟屏幕内，避免换分辨率/拔副屏后窗口丢失。
/// </summary>
public static class WindowPlacement
{
    /// <summary>默认位置与屏幕边缘的间距（DIP）。</summary>
    public const double DefaultMargin = 24;

    /// <summary>
    /// 计算启动时应使用的左上角坐标。
    /// </summary>
    /// <param name="left">保存的 X（null 表示没保存过）。</param>
    /// <param name="top">保存的 Y（null 表示没保存过）。</param>
    /// <param name="width">窗口宽度（DIP）。</param>
    /// <param name="height">窗口高度（DIP）。</param>
    /// <param name="screenLeft">虚拟屏幕左边界（多显示器时可能为负）。</param>
    /// <param name="screenTop">虚拟屏幕上边界。</param>
    /// <param name="screenWidth">虚拟屏幕宽度。</param>
    /// <param name="screenHeight">虚拟屏幕高度。</param>
    /// <returns>保证落在屏幕内的左上角坐标。</returns>
    public static (double Left, double Top) Clamp(
        double? left,
        double? top,
        double width,
        double height,
        double screenLeft,
        double screenTop,
        double screenWidth,
        double screenHeight)
    {
        if (!double.IsFinite(width) || width <= 0)
        {
            throw new ArgumentOutOfRangeException(nameof(width), "窗口宽度必须为正数。");
        }

        if (!double.IsFinite(height) || height <= 0)
        {
            throw new ArgumentOutOfRangeException(nameof(height), "窗口高度必须为正数。");
        }

        if (!double.IsFinite(screenWidth) || screenWidth <= 0)
        {
            screenWidth = width + (2 * DefaultMargin);
        }

        if (!double.IsFinite(screenHeight) || screenHeight <= 0)
        {
            screenHeight = height + (2 * DefaultMargin);
        }

        double fallbackLeft = screenLeft + screenWidth - width - DefaultMargin;
        double fallbackTop = screenTop + DefaultMargin;

        double x = left is { } savedLeft && double.IsFinite(savedLeft) ? savedLeft : fallbackLeft;
        double y = top is { } savedTop && double.IsFinite(savedTop) ? savedTop : fallbackTop;

        double maxLeft = screenLeft + Math.Max(0, screenWidth - width);
        double maxTop = screenTop + Math.Max(0, screenHeight - height);

        return (Math.Clamp(x, screenLeft, maxLeft), Math.Clamp(y, screenTop, maxTop));
    }
}
```

要点：

- **同时缺一个就用默认**：只有 `Left/Top` 都在才认为是有效保存位置，避免"X 存了 Y 没存"造成贴边诡异位置；
- **非有限值**（`NaN/∞`，用户手改配置可能出现）当缺失处理；
- **窗口比屏幕大**时 `Math.Max(0, …)` 让 `maxLeft = screenLeft`，窗口贴左上角，至少有内容可见。

```csharp
/// <summary>图钉状态变化：立即持久化。</summary>
private void OnPinnedChanged(bool pinned)
{
    _settings = _settings with { IsPinned = pinned };
    if (!_store.TrySave(_settings))
    {
        Debug.WriteLine("LiteMon: 固定状态保存失败");
    }
}

/// <summary>拖动结束：记录新位置。</summary>
private void OnMoved(double left, double top)
{
    _settings = _settings with { WindowLeft = left, WindowTop = top };
    if (!_store.TrySave(_settings))
    {
        Debug.WriteLine("LiteMon: 窗口位置保存失败");
    }
}
```


> 原来的 `Left = WorkArea.Right - Width - 24` 计算删除，改为由 `App` 传入（默认位置的计算已移动到 `WindowPlacement.Clamp` 的 fallback 分支）。

#### 5.4.3 命中与拖动

```csharp
private void OnMouseLeftButtonDown(object sender, MouseButtonEventArgs e)
{
    if (e.ChangedButton != MouseButton.Left)
    {
        return;
    }

    Point position = e.GetPosition(this);

    if (position.Y < HeaderHeight)
    {
        if (position.X > Width - CloseZoneWidth)
        {
            Close();
            return;
        }

        if (position.X > Width - CloseZoneWidth - PinZoneWidth)
        {
            TogglePin();
            return;
        }
    }

    if (_isPinned)
    {
        return;   // 固定：拖不动
    }

    double beforeLeft = Left;
    double beforeTop = Top;

    try
    {
        DragMove();
    }
    catch (InvalidOperationException)
    {
        // 鼠标已释放时 DragMove 会抛异常，忽略
    }

    if (Math.Abs(Left - beforeLeft) > 0.5 || Math.Abs(Top - beforeTop) > 0.5)
    {
        _onMoved(Left, Top);
    }
}

private void TogglePin()
{
    _isPinned = !_isPinned;
    _view.SetPinned(_isPinned);
    _onPinnedChanged(_isPinned);

    if (_isPinned)
    {
        // "钉在当前停留的位置"：固定瞬间把实际坐标也记下来
        _onMoved(Left, Top);
    }
}

private void OnMouseMove(object sender, MouseEventArgs e)
{
    Point position = e.GetPosition(this);
    bool onButton = position.Y < HeaderHeight && position.X > Width - CloseZoneWidth - PinZoneWidth;

    Cursor = onButton ? Cursors.Hand : _isPinned ? Cursors.Arrow : Cursors.SizeAll;
}
```

细节：

- 拖动前后比较用 `0.5` 容差，避免 DPI 取整造成"没动也写盘"；
- `DragMove()` 抛异常（鼠标已松开）时**不保存**，位置本来也没变；
- 光标：按钮区手型、固定态箭头、可拖动态 `SizeAll`，让"能不能拖"一眼可见。

## 附录 B · 常见问题

**Q：固定之后任务栏还显示吗？**
不显示。面板本来就是 `ShowInTaskbar=false` 的置顶小窗，固定只影响"能否拖动"。

**Q：固定后还能改刷新间隔吗？**
能。固定只锁位置，不锁功能；右键菜单、图钉都仍然可点。

**Q：为什么不用 WPF 的 Button？**
面板整体是一个自绘 `FrameworkElement`（`PanelView`），没有控件树；为了一个 12px 的图标引入 Button 会带来透明背景命中、模板样式、焦点框等一堆问题，成本远高于画两个形状。

**Q：位置存的是物理像素吗？**
不是，存 DIP（逻辑像素）。物理像素在 125%/150%/200% 之间切换会出现明显漂移。
