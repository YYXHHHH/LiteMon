## 0. 怎么用这份文档

### 0.1 定位

技术方案回答"为什么这样做"，本手册回答"**今天做什么、写成什么样、怎么验证**"。每一节都包含四件事：

| 要素 | 含义 |
|---|---|
| 入口条件 | 开始本节前必须已完成的事 |
| 实现步骤 | 文件级、命令级、代码级的操作 |
| 验收标准 | 可复现、可观测，不能"我觉得可以了" |
| 提交拆分 | 建议的 commit/PR 粒度，避免一次性巨型提交 |

### 0.2 按角色阅读

| 角色 | 建议路径 |
|---|---|
| 单人全栈 | 按 §1 → §3 → §4 → §5 → §6 → §7 → §8 顺序推进 |
| 新加入的开发者 | §0 → §1 → §2 → §4（先跑通测试再改代码） |
| 测试 / QA | §3.4 判定标准 → §8 测试指南 → §9 调试手册 |
| 发布负责人 | §10 CI/CD → §11 质量门禁 → §8.10 回归清单 |

### 0.3 里程碑映射

| 里程碑 | 周期 | 对应章节 | 完成标志 |
|---|---|---|---|
| M0 技术验证 | 1 周 | §3 | 5 个实验通过，输出验证报告，Go/No-Go 决策 |
| M1 MVP | 3 周 | §4、§5 | 可 1 s 刷新、可开机自启、可打包分发的竖版面板 |
| M2 体验 | 2 周 | §6 | 横条/主题/告警/多屏/DPI 全部可用 |
| M3 发布 | 2 周 | §7 | 安装包签名、更新器、诊断包、历史曲线、回归通过 |

### 0.4 约定

- 所有命令默认在**仓库根目录**执行。
- 代码块标注语言；C# 代码默认启用 `Nullable` 与 `TreatWarningsAsErrors`。
- "验收"一律要求**能在干净机器上复现**；只在开发机上成立不算通过。
- 每个任务完成时勾选本节末尾的 checklist，并更新 `docs/进度.md`（见 §11.4）。

## 2. 架构落地与编码规范

### 2.1 启动序列（组合根唯一）

`App.xaml.cs` 只做三件事：注册服务、处理未捕获异常、启动主窗口。

```csharp
public partial class App : Application
{
    private readonly IHost _host;

    public App()
    {
        _host = Host.CreateDefaultBuilder()
            .ConfigureServices(services =>
            {
                services.AddSingleton<SettingsStore>();
                services.AddSingleton<SnapshotBus>();
                services.AddSingleton<ISnapshotSource>(sp => sp.GetRequiredService<SnapshotBus>());
                services.AddSingleton<ISensorProvider, CpuProvider>();
                services.AddSingleton<ISensorProvider, MemoryProvider>();
                services.AddSingleton<ISensorProvider, NetworkProvider>();
                services.AddSingleton<ISensorProvider, DiskProvider>();
                services.AddSingleton<ISensorProvider, NvmlProvider>();
                services.AddSingleton<ISensorProvider, LhmProvider>();
                services.AddSingleton<SamplingService>();
                services.AddHostedService(sp => sp.GetRequiredService<SamplingService>());
                services.AddSingleton<MainWindow>();
            })
            .Build();
    }

    protected override void OnStartup(StartupEventArgs e)
    {
        DispatcherUnhandledException += (_, args) =>
        {
            Log.Fatal(args.Exception, "UI 线程未处理异常");
            args.Handled = true;   // 已在日志中留下现场；避免闪退
        };
        AppDomain.CurrentDomain.UnhandledException += (_, args) =>
            Log.Fatal(args.ExceptionObject as Exception, "后台线程未处理异常");

        _host.Start();
        _host.Services.GetRequiredService<MainWindow>().Show();
        base.OnStartup(e);
    }

    protected override void OnExit(ExitEventArgs e)
    {
        // 关闭顺序：停采样 → 停驱动 → 落盘 → 释放 Host
        _host.StopAsync(TimeSpan.FromSeconds(3)).GetAwaiter().GetResult();
        _host.Dispose();
        base.OnExit(e);
    }
}
```

**规则**：除 `App` 与 `MainWindow` 外，任何类不得 `new` 出另一个服务；一律构造注入。禁止服务定位器（`ServiceLocator.Get<T>()`）。

> 上例中的 `Log` 是项目内的静态日志门面（内部持有 `ILoggerFactory`，在 `App` 构造时初始化），实现放在 `LiteMon.Diagnostics`；不要让每个类自己 `new LoggerFactory`。

### 2.2 生命周期与关闭顺序

```
Start
 ├─ SettingsStore.Load()            （失败 → 默认值 + 备份坏文件）
 ├─ SamplingService.StartAsync()
 │    ├─ 依能力矩阵实例化 Provider（失败的标记 Disabled，不阻断启动）
 │    ├─ 首轮采样（异步，不阻塞首帧）
 │    └─ 启动快/中/慢三通道
 └─ MainWindow.Show()               （先绘制缓存快照，再等首轮数据）

Stop
 ├─ 取消 CancellationTokenSource
 ├─ 等采样线程退出（超时 2 s，超时就放弃，不能卡住退出）
 ├─ 各 Provider.DisposeAsync()      （逆序；LHM 最后关闭，因为它持有驱动）
 ├─ SettingsStore.Flush()
 └─ 日志 Flush + 关闭
```

### 2.3 线程与并发规范

| 规则 | 说明 |
|---|---|
| UI 线程不调用传感器 | 任何 `Provider.Poll` / `Computer.Update` 都不得出现在 UI 线程 |
| 采样线程不碰 UI 对象 | 只写 `SnapshotBuilder`，通过 `SnapshotBus` 发布 |
| 事件在采样线程触发 | 订阅方（UI）必须自行 `Dispatcher.BeginInvoke` |
| 禁止 `lock` + 阻塞等待 | 采样线程只用无锁/单线程写；需要同步时用 `Interlocked` / `Volatile` |
| LHM 单线程独占 | `Computer` 及其 `Hardware` 对象不是线程安全的，只允许采样线程访问 |
| 取消要传递 | 所有等待使用 `CancellationToken`，禁止裸 `Thread.Sleep(1000)` |
| 线程命名 | `sampler-fast`、`sampler-medium`、`sampler-slow`，便于 Process Explorer 定位 |

### 2.4 错误处理与状态语义

```csharp
// Provider 边界统一包装：不把异常抛给调度器
try
{
    provider.Poll(writer, nowMs);
}
catch (Exception ex) when (ex is not OperationCanceledException)
{
    _log.LogError(new EventId(2002, "PollFailed"), ex, "{Provider} 采样失败", provider.Name);
    writer.MarkUnavailable(provider.SupportedMetrics);   // 该项显示 --
    _failures[provider.Name]++;                           // 连续失败进入退避
}
```

| 状态 | 触发 | UI 表现 |
|---|---|---|
| `Ok` | 正常读数 | 正常颜色 |
| `Unavailable` | 传感器不存在 / 无权限 / 驱动未加载 | `--`，悬浮说明原因 |
| `Stale` | 本轮失败但上一轮有值（< 30 s） | 数字变灰 |
| `Error` | 连续失败 > 3 次 | `--` + 红色小点 + 记日志 |

**禁止**：用 0 表示"读不到"；用异常控制正常流程；吞掉异常不记日志。

### 2.5 日志规范

统一使用 `Microsoft.Extensions.Logging`，字段化输出，便于诊断包解析。

| EventId | 名称 | 级别 | 关键字段 |
|---|---|---|---|
| 1000 | AppStart | Information | version, os, arch |
| 1001 | SettingsLoadFailed | Warning | path, reason, backupPath |
| 2000 | ProviderInit | Information | provider, ok, ms |
| 2001 | PollSlow | Warning | provider, ms |
| 2002 | PollFailed | Error | provider, exception |
| 3000 | DriverLoadFailed | Error | reason, admin |
| 3001 | DriverLoaded | Information | version |
| 4000 | ThemeReload | Information | id, ok |
| 5000 | AlertRaised | Information | metric, value, threshold |
| 9000 | UpdateCheck | Information | current, latest, source |

要求：日志中**不得**出现用户名、主机名、IP、序列号；异常堆栈保留。

### 2.6 命名与代码风格

| 项 | 规则 |
|---|---|
| 命名空间 | `LiteMon.<项目>.<子域>`，如 `LiteMon.Sensors.Cpu` |
| 私有字段 | `_camelCase` |
| 异步方法 | 后缀 `Async`，且必须有 `CancellationToken` 参数（除纯内存操作） |
| 接口 | `I` 前缀；实现类用具体名（`NvmlProvider`） |
| 常量 | `PascalCase`；magic number 必须命名 |
| 文件 | 一个文件一个主要类型（嵌套小类型除外） |
| 可空 | 开启 `Nullable`；对外 API 显式标注 |
| 注释 | 解释"为什么"，不解释"是什么"；公开 API 写 XML 文档 |

### 2.7 性能红线（评审直接打回）

1. 热路径（每帧/每秒）出现 LINQ、`string.Format`、闭包分配。
2. `OnRender` 内创建 `FormattedText`、`Pen`、`Brush`（应缓存并 `Freeze`）。
3. 每轮采样重复创建 PDH 查询 / 重复 `nvmlInit` / 重复枚举设备。
4. 任何形式的 `Thread.Sleep`。
5. UI 线程同步等待（`.Result`、`.Wait()`）。
6. 事件订阅未取消（内存泄漏重灾区）。
7. 每秒分配 > 16 KB（用 `dotnet-counters` 观察 Gen0 速率）。

### 2.8 可测性设计

- 所有 Provider 只依赖接口（`IClock`、`ISystemApi`），硬件调用放最薄的一层（`Interop`），便于 Fake。
- 时间通过 `IClock` 注入（`Stopwatch` 实现），测试用 `FakeClock` 推进。
- 渲染器接受 `Snapshot` 与 `Theme`，不依赖窗口；可在离屏 `RenderTargetBitmap` 上测试。

### 3.4 S3：NVMe 温度（IOCTL）

```csharp
const uint IOCTL_STORAGE_QUERY_PROPERTY = 0x002D1400;
const int StorageDeviceTemperatureProperty = 47;   // 正式代码请用 CsWin32 的枚举

[StructLayout(LayoutKind.Sequential)]
struct STORAGE_PROPERTY_QUERY { public int PropertyId; public int QueryType; public byte AdditionalParameters; }

using var handle = File.OpenHandle(@"\\.\PhysicalDrive0", FileMode.Open, FileAccess.Read, FileShare.ReadWrite);

var query = new STORAGE_PROPERTY_QUERY { PropertyId = StorageDeviceTemperatureProperty, QueryType = 0 };
int qSize = Marshal.SizeOf<STORAGE_PROPERTY_QUERY>();
IntPtr qPtr = Marshal.AllocHGlobal(qSize);
Marshal.StructureToPtr(query, qPtr, false);

byte[] buffer = new byte[512];
bool ok = DeviceIoControl(handle, IOCTL_STORAGE_QUERY_PROPERTY, qPtr, (uint)qSize,
                          buffer, (uint)buffer.Length, out _, IntPtr.Zero);
Marshal.FreeHGlobal(qPtr);

if (!ok) { Console.WriteLine($"IOCTL failed: {Marshal.GetLastWin32Error()}"); return; }

// STORAGE_TEMPERATURE_DATA_DESCRIPTOR: Version(4) Size(4) Critical(2) Warning(2) InfoCount(2) R0(1) R1(4)
short tempKelvin = BitConverter.ToInt16(buffer, 16 + 2);  // Info[0].Temperature 偏移见结构体
Console.WriteLine($"NVMe: {tempKelvin - 273.15:F0} °C");
```

> 偏移量随结构体对齐变化，**正式实现必须用 `Marshal.PtrToStructure` 而不是魔数偏移**。本实验只验证"能否拿到合理温度以及是否需要管理员"。

```csharp
public sealed class Snapshot
{
    public static readonly Snapshot Empty = new(0, 0, Array.Empty<MetricSample>(), DeviceSet.Empty);

    public long TimestampMs { get; }
```

### 4.3 SnapshotBuilder 与 SnapshotBus

```csharp
public sealed class SnapshotBuilder
{
    private readonly MetricSample[] _slots = new MetricSample[(int)MetricId.Count];
    private long _nowMs;
    private long _sequence;

    public SnapshotBuilder() => Clear();

    private void Clear()
    {
        for (int i = 0; i < _slots.Length; i++)
            _slots[i] = new MetricSample((MetricId)i, 0, MetricStatus.Unavailable, 0);
    }

    public void Begin(long nowMs) => _nowMs = nowMs;

    public void Write(MetricId id, double value, MetricStatus status = MetricStatus.Ok)
        => _slots[(int)id] = new MetricSample(id, value, status, _nowMs);

    public void MarkUnavailable(IEnumerable<MetricId> ids)
    {
        foreach (var id in ids) _slots[(int)id] = new MetricSample(id, 0, MetricStatus.Unavailable, _nowMs);
    }

    public Snapshot Build()
    {
        var copy = (MetricSample[])_slots.Clone();
        for (int i = 0; i < copy.Length; i++)
        {
            var s = copy[i];
            // 12 s 必须大于最慢采样档（10 s），否则慢通道指标会被误判为过期
        if (s.Status == MetricStatus.Ok && _nowMs - s.TimestampMs > 12_000)
                copy[i] = s with { Status = MetricStatus.Stale };
        }
        return new Snapshot(_sequence++, _nowMs, copy, DeviceSet.Empty);
    }
}
```

```csharp
public sealed class SnapshotBus : ISnapshotSource
{
    private Snapshot _current = Snapshot.Empty;

    public Snapshot Current => Volatile.Read(ref _current);

    public event EventHandler<Snapshot>? Updated;

    public void Publish(Snapshot snapshot)
    {
        Volatile.Write(ref _current, snapshot);
        Updated?.Invoke(this, snapshot);      // 注意：在采样线程触发
    }
}
```

### 4.4 采样调度

**实现决策**：M1 用**单个采样线程 + 内部节拍**（快 1 s、中 2 s、慢 10 s），而不是三个线程。理由：LHM 本身要求单线程独占；分频采样不会互相竞争；实现与测试都更简单。若 M2 发现 LHM 的 8 ms 抖动影响快通道，再把中/慢通道拆出去，接口不变。

```csharp
public sealed class SamplingService : BackgroundService
{
    private readonly IReadOnlyList<ISensorProvider> _providers;
    private readonly SnapshotBuilder _builder = new();
    private readonly SnapshotBus _bus;
    private long _tick;

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        foreach (var p in _providers)
            await ProviderRuntime.InitializeAsync(p, ct);       // 失败 → Disabled，不阻断

        using var timer = new PeriodicTimer(TimeSpan.FromSeconds(1));
        while (await timer.WaitForNextTickAsync(ct))
        {
            _builder.Begin(Environment.TickCount64);
            PollByCadence(ProviderCadence.Fast);

            if (_tick % 2 == 0)  PollByCadence(ProviderCadence.Medium);
            if (_tick % 10 == 0) PollByCadence(ProviderCadence.Slow);

            _bus.Publish(_builder.Build());
            _tick++;
        }
    }

    private void PollByCadence(ProviderCadence cadence)
    {
        foreach (var p in _providers)
        {
            if (!p.IsEnabled || p.Cadence != cadence) continue;
            try { p.Poll(_builder, Environment.TickCount64); }
            catch (Exception ex) { ProviderRuntime.HandleFailure(p, ex, _builder); }
        }
    }
}
```

**掉帧补偿**：若某一轮耗时超过 1 s，`PeriodicTimer` 会跳过已错过的节拍（不补偿），这是我们要的行为——宁可丢一帧，也不要追帧导致 CPU 尖峰。日志记 `PollSlow`（> 200 ms）。

### 4.5 Provider 契约与能力协商

```csharp
public enum ProviderCadence { Fast, Medium, Slow }

public sealed record ProviderCapabilities(
    IReadOnlySet<MetricId> Metrics,
    bool RequiresAdmin,
    bool RequiresDriver);

public interface ISensorProvider : IAsyncDisposable
{
    string Name { get; }
    ProviderCadence Cadence { get; }
    ProviderCapabilities Capabilities { get; }
    bool IsEnabled { get; }
    ValueTask InitializeAsync(CancellationToken ct);
    void Poll(IMetricWriter writer, long nowMs);
}
```

**契约（所有 Provider 必须满足，用契约测试覆盖）**：

1. `Poll` 不抛异常（实现内部捕获并写 `Unavailable`），超时 ≤ 预算是硬要求。
2. 只写自己 `Capabilities.Metrics` 里的 ID。
3. `InitializeAsync` 失败时 `IsEnabled = false`，不抛出到调度器。
4. `DisposeAsync` 可重复调用，且 2 s 内完成。
5. 不依赖 UI 线程，不做 IO 阻塞（除必要的设备枚举）。

### 4.6 CPU Provider

**数据源**：PDH `% Processor Utility`（快）；`NtQuerySystemInformation` 每核（快）；`CallNtPowerInformation` 频率（快）。

```csharp
public sealed class CpuProvider : ISensorProvider
{
    private PdhQuery? _utility;
    private readonly CpuCoreTimes _cores = new();

    public string Name => "cpu";
    public ProviderCadence Cadence => ProviderCadence.Fast;
    public bool IsEnabled { get; private set; }
    public ProviderCapabilities Capabilities { get; } = new(
        new HashSet<MetricId> { MetricId.CpuLoad, MetricId.CpuCoreMax, MetricId.CpuCoreAvg, MetricId.CpuClockMhz },
        RequiresAdmin: false, RequiresDriver: false);

    public ValueTask InitializeAsync(CancellationToken ct)
    {
        _utility = PdhQuery.TryOpen(@"\Processor Information(_Total)\% Processor Utility");
        _cores.Reset();
        IsEnabled = true;
        return ValueTask.CompletedTask;
    }

    public void Poll(IMetricWriter w, long nowMs)
    {
        if (_utility is { } q && q.TryGetDouble(out var util))
            w.Write(MetricId.CpuLoad, Math.Clamp(util, 0, 100));

        var (avg, max) = _cores.Sample();
        w.Write(MetricId.CpuCoreAvg, avg);
        w.Write(MetricId.CpuCoreMax, max);

        if (PowerInfo.TryGetCurrentMhz(out var mhz) && mhz > 0)
            w.Write(MetricId.CpuClockMhz, mhz);
    }

    public ValueTask DisposeAsync() { _utility?.Dispose(); return ValueTask.CompletedTask; }
}
```

**坑**：

- PDH 首次 `Collect` 是基线，**第一次读数为 0**，要丢弃并标记 `Unavailable` 直到第二轮。
- 中文系统的计数器名是本地化的，必须 `PdhAddEnglishCounterW`。
- 虚拟机里 `CallNtPowerInformation` 可能返回 0 MHz，写入前判 `> 0`。
- `% Processor Utility` 可能超过 100（睿频），显示时钳到 100。

**测试点**：空转 5 s 平均 < 10%；跑满一个核后 max 接近 100%；PDH 打不开时自动回退 NtQuery。

### 4.7 内存 Provider

```csharp
[StructLayout(LayoutKind.Sequential)]
struct MEMORYSTATUSEX
{
    public uint Length, MemoryLoad;
    public ulong TotalPhys, AvailPhys, TotalPageFile, AvailPageFile;
    public ulong TotalVirtual, AvailVirtual, AvailExtendedVirtual;
}

public void Poll(IMetricWriter w, long nowMs)
{
    var m = new MEMORYSTATUSEX { Length = (uint)Marshal.SizeOf<MEMORYSTATUSEX>() };
    if (!GlobalMemoryStatusEx(ref m)) { w.Write(MetricId.MemUsedPercent, 0, MetricStatus.Unavailable); return; }

    w.Write(MetricId.MemUsedPercent, 100.0 - 100.0 * m.AvailPhys / m.TotalPhys);
    w.Write(MetricId.MemTotalBytes, m.TotalPhys);
    w.Write(MetricId.MemAvailableBytes, m.AvailPhys);
    w.Write(MetricId.MemUsedBytes, m.TotalPhys - m.AvailPhys);
}
```

**坑**：`Length` 必须赋值，否则调用失败（`ERROR_INVALID_PARAMETER`）。任务管理器的"使用中"与 `Total-Available` 略有差异（缓存口径），误差 < 3% 属正常，文档中不要承诺 100% 一致。

### 4.8 网络 Provider

```csharp
public sealed class NetworkProvider : ISensorProvider
{
    private ulong _prevIn, _prevOut;
    private long _prevTs;
    private uint _ifIndex;
    private bool _primed;

    public void Poll(IMetricWriter w, long nowMs)
    {
        if (!MibIf.TryGet(_ifIndex, out var row)) { MarkAllUnavailable(w); return; }

        if (!_primed || nowMs <= _prevTs)
        {
            _prevIn = row.InOctets; _prevOut = row.OutOctets; _prevTs = nowMs; _primed = true;
            w.Write(MetricId.NetTotalIn, row.InOctets);
            w.Write(MetricId.NetTotalOut, row.OutOctets);
            return;                      // 首轮没有速率
        }

        double dt = (nowMs - _prevTs) / 1000.0;
        w.Write(MetricId.NetDownBps, (row.InOctets - _prevIn) / dt);
        w.Write(MetricId.NetUpBps, (row.OutOctets - _prevOut) / dt);
        w.Write(MetricId.NetTotalIn, row.InOctets);
        w.Write(MetricId.NetTotalOut, row.OutOctets);

        _prevIn = row.InOctets; _prevOut = row.OutOctets; _prevTs = nowMs;
    }
}
```

**选择网卡**：过滤 `OperStatus == IfOperStatusUp` 且 `HardwareInterface == true`；排除 Hyper-V/vEthernet/Loopback/Teredo；多网卡时按"默认路由接口"优先（`GetBestInterface`），其次按流量最大，再其次交给用户手选。

**坑**：`InOctets` 是 64 位，不会在人类时间尺度回绕；但**网卡切换**（Wi-Fi 漫游、VPN 连接）会让累计值跳变，必须检测并重建基线，否则会出现负速率或几 GB/s 的尖峰。

### 4.9 磁盘 Provider

PDH 计数器：`\\PhysicalDisk(_Total)\\Disk Read Bytes/sec`、`Disk Write Bytes/sec`。

- 用 `PhysicalDisk` 而不是 `LogicalDisk`（后者按分区重复计数）。
- 实例名 `_Total` 是聚合；用户选择单块盘时用 `PhysicalDisk(n C:)` 形式，**不要用盘符**（会变）。
- 通过 `Win32_DiskDrive` 的 `PNPDeviceID` 或 `SerialNumber` 建立稳定标识。

NVMe 温度由独立 Provider 负责（见 4.12），不要混在 PDH 里。

### 4.10 NVML Provider（NVIDIA）

```csharp
public sealed class NvmlProvider : ISensorProvider
{
    private IntPtr _device;
    private NvmlMemory _memTotal;

    public ProviderCadence Cadence => ProviderCadence.Medium;   // 2 s

    public ValueTask InitializeAsync(CancellationToken ct)
    {
        if (!NvmlNative.TryInit()) { IsEnabled = false; return ValueTask.CompletedTask; }
        _device = NvmlNative.Handle(0);            // 多卡：按设置或按"有显示输出"选择
        IsEnabled = _device != IntPtr.Zero;
        return ValueTask.CompletedTask;
    }

    public void Poll(IMetricWriter w, long nowMs)
    {
        if (NvmlNative.GetUtilization(_device, out var u) == 0)
            w.Write(MetricId.GpuLoad, u.Gpu);

        if (NvmlNative.GetTemperature(_device, 0, out var t) == 0)
            w.Write(MetricId.GpuTemp, t);

        if (NvmlNative.GetMemory(_device, out var mem) == 0)
        {
            w.Write(MetricId.GpuMemUsedMb, mem.Used / 1024.0 / 1024.0);
            w.Write(MetricId.GpuMemTotalMb, mem.Total / 1024.0 / 1024.0);
        }

        if (NvmlNative.GetPower(_device, out var mw) == 0)
            w.Write(MetricId.GpuPowerW, mw / 1000.0);
    }
```

**坑**：

- 驱动更新/睡眠唤醒后 `nvmlInit` 会失效，需要重新初始化（每 60 s 重试一次，成功前保持 `Unavailable`）。
- 笔记本可能是 Optimus：独显空闲时 NVML 返回 0 W / 0%，这是正常的。
- 多卡时不要"自动选第一个"就完事，UI 必须能选，且选择要持久化。
- `nvml.dll` 在 `System32`，但旧驱动可能没有 `_v2` 后缀函数，需按驱动版本回退。

```csharp
        foreach (var hw in _computer!.Hardware)
        {
            hw.Update();
            foreach (var s in hw.Sensors)

            }
        }
    }

    private void BuildMap()
    {
        foreach (var hw in _computer!.Hardware)
            foreach (var s in hw.Sensors)
                if (MapSensor(hw, s) is { } id) _map[s.Identifier] = id;
    }

    private static MetricId? MapSensor(IHardware hw, ISensor s) => (hw.HardwareType, s.SensorType, s.Name) switch
    {

        (HardwareType.Cpu, SensorType.Power, _) => MetricId.CpuPowerW,
        (HardwareType.Motherboard or HardwareType.SuperIO, SensorType.Fan, _) => MetricId.FanRpm,
```

### 4.12 NVMe Provider

- 枚举 `\\.\PhysicalDrive0..31`，用 `STORAGE_PROPERTY_QUERY` 判定是否为 NVMe（`STORAGE_DEVICE_DESCRIPTOR.BusType == BusTypeNvme`）。
- 读取温度用 `StorageDeviceTemperatureProperty`，优先取 `CriticalTemperature` 之外的 `Info[0].Temperature`（开尔文 → ℃）。
- 设备标识用 `DeviceNumber + SerialNumber`，不用盘符。
- 失败（`ERROR_ACCESS_DENIED`/`ERROR_INVALID_FUNCTION`）→ 该项 `Unavailable`，并记录一次诊断事件，不要每轮刷日志。

### 4.13 系统信息 Provider（一次性）

- `Win32_Processor`（型号、核数、最大频率）、`Win32_BaseBoard`、`Win32_BIOS`、`Win32_PhysicalMemory`（容量/频率/厂商）、`Win32_VideoController`。
- 只在启动时执行一次，结果缓存进 `DeviceSet`；**不要**放进 1 s 循环（WMI 单次 20–200 ms）。
- 所有 WMI 查询都要包 `ManagementException`，在精简版系统/容器里 WMI 可能不可用。

### 5.2 加载、保存、迁移、回滚

```csharp
public sealed class SettingsStore
{
    public const int CurrentVersion = 1;
    private readonly string _path = Path.Combine(AppContext.BaseDirectory, "settings.json");
    private readonly ILogger<SettingsStore> _log;
    private readonly SemaphoreSlim _gate = new(1, 1);
    private CancellationTokenSource? _debounce;

    public AppSettings Current { get; private set; } = new();

    public void Load()
    {
        try
        {
            if (!File.Exists(_path)) { Current = new AppSettings(); return; }
            var json = File.ReadAllText(_path);
            var root = JsonNode.Parse(json)!.AsObject();
            Current = Migrate(root);
        }
        catch (Exception ex)
        {
            _log.LogWarning(new EventId(1001, "SettingsLoadFailed"), ex, "配置损坏，回滚默认值");
            TryRestoreBackup();
        }
    }

    public void SaveDebounced()
    {
        _debounce?.Cancel();
        _debounce = new CancellationTokenSource();
        var token = _debounce.Token;
        _ = Task.Delay(500, token).ContinueWith(t =>
        {
            if (!t.IsCanceled) _ = SaveAsync();
        }, TaskScheduler.Default);
    }

    public async Task SaveAsync()
    {
        await _gate.WaitAsync();
        try
        {
            Directory.CreateDirectory(Path.GetDirectoryName(_path)!);
            var json = JsonSerializer.Serialize(Current, JsonOptions);
            WriteAtomic(_path, json);
        }
        finally { _gate.Release(); }
    }

    private static void WriteAtomic(string path, string json)
    {
        var tmp = path + ".tmp";
        File.WriteAllText(tmp, json, new UTF8Encoding(false));
        if (File.Exists(path)) File.Replace(tmp, path, path + ".bak", ignoreMetadataErrors: true);
        else File.Move(tmp, path);
    }

    private static AppSettings Migrate(JsonObject root)
    {
        int version = root["schemaVersion"]?.GetValue<int>() ?? 0;
        if (version > CurrentVersion)
            throw new NotSupportedException($"配置版本 {version} 高于程序支持的 {CurrentVersion}");

        while (version < CurrentVersion)
        {
            root = version switch
            {
                0 => MigrateV0ToV1(root),
                _ => root,
            };
            version++;
            root["schemaVersion"] = version;
        }
        return root.Deserialize<AppSettings>()!;
    }
}
```

```csharp
private void OnSnapshotPublished(object? sender, Snapshot snapshot)
{
    if (!Dispatcher.CheckAccess())
    {
        Dispatcher.BeginInvoke(DispatcherPriority.Render, new Action(() => OnSnapshotPublished(sender, snapshot)));
        return;
    }
    _target = snapshot;
    if (_animating) return;
    _animating = true;
    CompositionTarget.Rendering += OnFrame;
}

{
```

### 6.3 告警引擎

```csharp
public sealed record AlertRule(double High, double Hysteresis = 3, int DebounceMs = 3000, int CooldownMs = 300_000);

public sealed class AlertEngine
{
    private enum State { Normal, Raising, Raised }
    private readonly Dictionary<MetricId, (State State, long Since, long LastNotify)> _state = new();
    private readonly IReadOnlyDictionary<MetricId, AlertRule> _rules;

    public IReadOnlyList<AlertEvent> Observe(Snapshot s, long nowMs)
    {
        List<AlertEvent>? events = null;
        foreach (var (id, rule) in _rules)
        {
            var sample = s.Get(id);
            if (sample.Status != MetricStatus.Ok) continue;

            var st = _state.TryGetValue(id, out var v) ? v : (State.Normal, nowMs, 0L);
            switch (st.State)
            {
                case State.Normal when sample.Value >= rule.High:
                    st = (State.Raising, nowMs, st.LastNotify);
                    break;
                case State.Raising when sample.Value < rule.High - rule.Hysteresis:
                    st = (State.Normal, nowMs, st.LastNotify);
                    break;
                case State.Raising when nowMs - st.Since >= rule.DebounceMs:
                    if (nowMs - st.LastNotify >= rule.CooldownMs)
                    {
                        (events ??= []).Add(new AlertEvent(id, sample.Value, rule.High, nowMs));
                        st = (State.Raised, st.Since, nowMs);
                    }
                    break;
                case State.Raised when sample.Value < rule.High - rule.Hysteresis:
                    st = (State.Normal, nowMs, st.LastNotify);
                    break;
            }
            _state[id] = st;
        }
        return (IReadOnlyList<AlertEvent>?)events ?? Array.Empty<AlertEvent>();
    }
}
```

**必须做的边界测试**：阈值抖动（85 → 84.9 → 85.1）不重复告警；持续高温只告警一次；冷却期后再次越线会再告警；`Unavailable` 不触发也不需要解除。

### 6.4 DPI 与多屏

**app.manifest**：

```xml
<application xmlns="urn:schemas-microsoft-com:asm.v3">
  <windowsSettings>
    <dpiAwareness xmlns="http://schemas.microsoft.com/SMI/2016/WindowsSettings">PerMonitorV2</dpiAwareness>
```

- 位置保存以"显示器 ID + 相对工作区偏移"记录，显示器拔插后能恢复。
- `DpiChanged` → 清空文本缓存 → `InvalidateVisual`。
- 每次移动后 `ClampToWorkArea`：`GetMonitorInfo` 返回 `rcWork`，留 8 DIP 边距。
- 竖版高度超出屏幕时，按行压缩或滚动（首版直接压缩到最小行高 18 DIP）。

### 6.5 边缘吸附、穿透、限制拖出屏幕

| 功能 | 实现 | 注意 |
|---|---|---|
| 吸附 | 距工作区边缘 < 20 DIP 时对齐 | 吸附后更新配置 |
| 自动收起 | 贴边 1.5 s 后滑出，仅留 3 DIP | 用 `GetCursorPos` 轮询 150 ms 判断"探出" |
| 鼠标穿透 | 切换 `WS_EX_TRANSPARENT` | 开启后必须能通过全局快捷键关闭 |
| 限制屏幕内 | 移动结束时钳制 | 多屏拔插后也要钳制 |
| 全局快捷键 | `RegisterHotKey` + `HwndSource.AddHook` | 冲突时提示并允许改键 |

### 6.6 动画

- 数值：指数平滑（`v += (target - v) * 0.35`），约 250 ms 收敛。
- 收起/展开：`DoubleAnimation` 150–200 ms，`QuadraticEase`。
- **尊重系统设置**："减少动画"开启时禁用全部动画（`SystemParameters.ClientAreaAnimation`）。
- 动画期间才订阅 `CompositionTarget.Rendering`，收敛即退订。

## 7. 发布就绪（M3，约 2 周）

### 7.1 历史数据

**写入策略**：1 s 原始数据只进内存环形缓冲（保留 10 min）；每分钟把过去 60 s 聚合成 avg/min/max 写入 SQLite，**一次事务批量插入**。

```sql
PRAGMA journal_mode = WAL;

CREATE TABLE IF NOT EXISTS sample_1m (
    metric  INTEGER NOT NULL,
    ts      INTEGER NOT NULL,      -- Unix 秒，分钟对齐
    avg     REAL NOT NULL,
    min     REAL NOT NULL,
    max     REAL NOT NULL,
    PRIMARY KEY (metric, ts)
) WITHOUT ROWID;

CREATE INDEX IF NOT EXISTS ix_sample_1m_ts ON sample_1m (ts);
```

- 保留 7 天；每天 03:00 删除过期行并 `PRAGMA incremental_vacuum`。
- 写库在后台线程，失败不重试超过 3 次（磁盘满时不要拖垮采样）。
- 容量估算：12 指标 × 1440 分钟 × 7 天 ≈ 12 万行 ≈ 6–8 MB。

```csharp
public abstract class SensorProviderContractTests : IAsyncLifetime
{
    protected abstract ISensorProvider CreateProvider();
```

## 9. 调试手册

### 9.1 症状 → 排查

| 症状 | 常见原因 | 排查步骤 | 处理 |
|---|---|---|---|
| 温度全部 `--` | 兼容模式 / 非管理员 / 虚拟机 / OEM EC 不暴露 | 看 `driver.txt`；管理员运行 spike；用 HWiNFO 对照 | 引导开启完整模式或隐藏该项 |
| PDH 读数恒 0 | 首次 Collect 是基线；或计数器损坏 | 第二轮再看；`lodctr /r` | 丢弃首轮；用 English counter |
| CPU% 与任务管理器差很多 | 用了 `% Processor Time` 而非 `% Processor Utility` | 检查计数器路径 | 换 Utility 或 NtQuery |
| NVML 初始化失败 | 驱动未加载 / 睡眠唤醒 / 无 N 卡 | `nvidia-smi`；看错误码（9 = DRIVER_NOT_LOADED） | 60 s 重试；无卡时禁用 Provider |
| NVMe 打开失败 (5) | 需要管理员 | 用管理员跑一次 | 提权或隐藏 |
| UI 卡顿 | UI 线程调传感器 / 文本未缓存 / 透明窗口 | dotnet-trace 看 UI 线程栈；看 OnRender 分配 | 见 §2.7 |
| 内存持续上涨 | 事件未退订 / 文本缓存无上限 / 日志缓冲 | VMMap 对比 1 h 快照；查 `+=` 订阅 | 弱事件/显式退订；缓存 LRU |
| 双屏文字模糊 | 未声明 PerMonitorV2 | 检查 manifest | 补 DPI 声明并重建缓存 |
| 改了 csproj 但错误还在（NU1010 / OutputType） | MSBuild Server 缓存了旧工程求值 | `dotnet build-server shutdown`；删除 `obj/` | 重建成功后再改代码 |
| PDH 返回 0xC0000BC0 / 路径无效 | 计数器路径漏了反斜杠（C# verbatim 字符串写错） | 打印实际 path 字符串 | 应为 @"\Processor Information(_Total)\% Processor Utility" |
| 启动即崩溃 | 配置损坏 / 驱动异常 | `--safe-mode` 启动；看日志 | 回滚配置；禁用驱动 |
| 托盘图标消失 | explorer 重启 | 监听 `TaskbarCreated` 消息 | 收到后重新添加图标 |
| 更新失败 | 网络 / 哈希 / 权限 | 看日志中的 URL、HTTP 码、哈希 | 换镜像；提示手动下载 |
| 开机不自启 | 计划任务被组策略禁用 | `schtasks /Query /TN LiteMon` | 回退 Run 键并提示 |

### 9.2 工具与命令

```bash
dotnet-counters monitor -p <pid> --counters System.Runtime,Microsoft.WindowsDesktop.App
dotnet-trace collect -p <pid> --duration 00:00:30
dotnet-dump collect -p <pid>
dotnet-dump analyze <dump> -c "clrstack" -c "exit"

# ETW（卡顿/掉帧）
wpr -start GeneralProfile -filemode
wpr -stop trace.etl
```

| 工具 | 用途 |
|---|---|
| Process Explorer | 句柄、线程、GDI 对象、加载的驱动 |
| VMMap | 托管/非托管内存分布 |
| DebugView | `OutputDebugString` 与驱动日志 |
| PerfView / dotnet-trace | CPU 采样、分配热点 |
| WinDbg | 蓝屏 dump 分析（`!analyze -v`） |

### 9.3 现场取证流程

1. 让用户点"导出诊断包"（不要只让截图）。
2. 对比 `capabilities.json` 与预期：Provider 是否启用、失败原因。
3. 看 `metrics-5min.csv`：是"没数据"还是"数据错"。
4. 看日志 EventId：2002 采样异常、3000 驱动失败、1001 配置损坏。
5. 仍无法复现 → 提供 `--safe-mode`、便携版、关闭驱动三种组合让用户试。

## 10. CI/CD

### 10.1 GitHub Actions

```yaml
name: ci

on:
  push: { branches: [main] }
  pull_request:
  workflow_dispatch:

jobs:
  build-test:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.0.x'
          global-json-file: global.json

      - run: dotnet restore
      - run: dotnet build -c Release --no-restore -warnaserror
      - run: pwsh build/test.ps1 -Configuration Release -NoBuild
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: test-results, path: '**/TestResults/**' }

      - name: Publish (framework-dependent)
        run: ./build/publish.ps1 -Runtime win-x64
      - uses: actions/upload-artifact@v4
        with: { name: LiteMon-win-x64, path: artifacts/publish/win-x64/** }

  release:
    if: startsWith(github.ref, 'refs/tags/v')
    needs: build-test
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with: { dotnet-version: '10.0.x' }
      - run: ./build/publish.ps1 -Runtime win-x64
      - name: Sign
        run: signtool sign /fd SHA256 /td SHA256 /tr http://timestamp.digicert.com /a artifacts/publish/win-x64/LiteMon.exe
        env: { SIGN_CERT: ${{ secrets.SIGN_CERT }} }   # 证书注入方式按实际调整
      - uses: softprops/action-gh-release@v2
        with:
          files: artifacts/publish/win-x64/LiteMon.exe
          generate_release_notes: true
```

**注意**：签名证书不要以明文进仓库；用 GitHub Secrets + 证书导入步骤，或走自托管 runner。

### 10.2 版本与变更日志

- SemVer：`MAJOR.MINOR.PATCH`；破坏配置格式 → MAJOR；新功能 → MINOR；修复 → PATCH。
- `CHANGELOG.md` 按 `Added / Changed / Fixed / Known Issues` 分组。
- 每次发版更新 `Directory.Build.props` 的 `Version` 与安装器版本，二者必须一致（CI 校验）。

### 10.3 发布与回滚

| 步骤 | 操作 |
|---|---|

## 11. 评审与质量门禁

### 11.1 PR 自查清单

- [ ] 改动是否有对应测试？没有则说明原因
- [ ] 是否在热路径引入了分配/LINQ/字符串拼接？
- [ ] 新增的 Provider 是否实现了契约测试？
- [ ] 新增配置字段是否更新了 Schema、迁移与文档？
- [ ] 是否引入了新依赖？许可证是否核对？
- [ ] 错误路径是否记日志且不吞异常？
- [ ] UI 改动是否在 100%/150% DPI 下看过？
- [ ] 是否更新了 CHANGELOG？

### 11.2 阶段质量门禁

| 里程碑 | 门禁 |
|---|---|
| M1 | 单元 + 契约测试全绿；Core 覆盖率 ≥ 60%；8 h 浸泡；无 S1/S2 |
| M2 | 渲染基准测试通过；24 h 浸泡；DPI 矩阵通过；无 S1/S2 |
| M3 | 全量回归；干净机安装/升级/卸载；签名验证；S3 ≤ 5 |

### 11.3 代码评审关注点（按重要性）

1. **正确性**：状态语义（Unavailable vs 0）、边界（首轮、网卡切换、设备消失）。
2. **资源**：句柄/驱动/SDK 是否释放；事件是否退订。
3. **性能**：是否在每秒/每帧路径上做重活。
4. **安全**：驱动只读、日志脱敏、更新校验。
5. **可维护性**：命名、分层、测试。
