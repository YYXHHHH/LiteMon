# 轻量硬件监控系统 LiteMon · 技术方案

> 参考项目：[Diorser/LiteMonitor](https://github.com/Diorser/LiteMonitor)（Windows 桌面硬件监控，约 2 MB，绿色版）
> 文档版本：v1.0 ｜ 2026-10-19 ｜ 目标平台：Windows 10 1809+ / Windows 11

---

## 0. 结论先行（TL;DR）

**做什么**：一个常驻系统托盘的桌面悬浮面板，1 秒级刷新 CPU / GPU / 内存 / 磁盘 / 网络，按需提供温度、风扇、功耗、电压；关机不占资源，开机即用。

**技术主线**（推荐方案）：

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | **C# + .NET 10 (LTS)** | 传感器生态（LibreHardwareMonitor）与 Windows 原生能力同栈，开发效率最高 |
| UI | **WPF + 自绘渲染**（DrawingVisual/OnRender） | 不依赖 Windows App SDK，框架依赖发布可做到 2–6 MB；自绘才能稳住 60 fps 与低内存 |
| 硬件访问 | **LibreHardwareMonitorLib**（PawnIO 签名驱动）+ NVML / ADLX / IGCL + PDH / IP Helper / IOCTL | 覆盖 CPU/主板/风扇/电压，GPU 走厂商 SDK 更准更快，通用指标零驱动 |
| 数据模型 | **每秒构建一次不可变 Snapshot** + 多速率采样线程 | 采集与渲染彻底解耦，天然线程安全，几乎零分配 |
| 配置 | **settings.json + 主题 JSON（带 schema 校验与热重载）** | 可备份、可迁移、可分享，和参考项目一致但补齐校验与迁移 |
| 进程模型 | **M1 单进程**；M3 可选拆分 *采集服务（提权）+ UI（低权限）* | 先用最简单形态验证，再按安全与稳定性需求演进 |

**三条硬约束**（决定成败，不是加分项）：

1. **无驱动也要能用**：CPU 利用率、内存、磁盘、网络、GPU 负载、NVMe 温度在普通用户权限下全部可读，覆盖 80% 场景；只有 CPU/主板温度、风扇、电压、功耗需要 ring0。
2. **温度是"尽力而为"**：笔记本 EC、OEM 定制主板、虚拟机、云主机读不到温度是常态。UI 必须显示 `--` 而不是 `0 °C`，并且能一键导出诊断包。
3. **不要用 WinRing0**：它已被 Microsoft Defender 标记为 `HackTool:Win32/Winring0`，参考项目也因此需要用户加白名单。改用开源的 **PawnIO 签名驱动**，并把驱动做成可选组件。

**排期**：M0 技术验证 1 周 → M1 MVP 3 周 → M2 体验打磨 2 周 → M3 发布就绪 2 周，合计约 8 周（单人全职）。

## 1. 产品定位与目标

### 1.1 一句话定义

> 一个"打开就看见、关掉不心疼"的 Windows 硬件仪表盘：常驻内存 < 60 MB、空闲 CPU < 0.3%、冷启动 < 1 s，实时显示利用率、温度、风扇、功耗、吞吐与流量。

### 1.2 目标用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 装机/超频玩家 | 压测、调风扇曲线时盯温度 | 温度准、刷新快、可置顶、不挡画面 |
| 开发者 / 工作站用户 | 编译、渲染、跑模型时看负载 | 低占用、GPU 显存与功耗、历史曲线 |
| 迷你主机 / NAS / HTPC | 长期无人值守 | 开机自启、远程可看、异常告警 |
| 普通办公用户 | 电脑变卡时排查 | 一眼看懂、不弹广告、不装全家桶 |

### 1.3 成功标准（可验收）

| 指标 | 目标值 | 测量方式 |
|---|---|---|
| 安装包体积 | ≤ 6 MB（框架依赖）/ ≤ 70 MB（自包含） | 发布产物 |
| 常驻内存（工作集） | ≤ 60 MB，稳态无增长 | 24 h 浸泡测试 + VMMap |
| 空闲 CPU | ≤ 0.3%（单核折算） | 任务管理器 / ETW |
| 冷启动到首帧 | ≤ 800 ms | 启动打点 |
| 数据刷新 | 1 s 档位，抖动 ≤ 50 ms | 采样时间戳统计 |
| 传感器采集耗时 | ≤ 2 ms/轮（无驱动）、≤ 8 ms/轮（含 ring0） | 内置性能计数器 |
| 崩溃率 | 7 日 < 0.1% 会话 | 匿名遥测（可选、默认关闭） |

### 1.4 明确的非目标

- ❌ 不做风扇调速 / 超频 / 电压写入（涉及写硬件，风险与合规成本高，M4 之后再评估）
- ❌ 首版不做 Linux / macOS（架构保留可移植性，见 3.1）
- ❌ 不做云端账号体系（本地优先；远程查看走 M4 的可选网关）
- ❌ 不追求"全传感器"（几百个传感器对普通用户是噪音，默认展示 8–12 项）

### 1.5 竞品与差异化

| 产品 | 定位 | 强项 | 短板 | 我们的差异 |
|---|---|---|---|---|
| HWiNFO64 | 专业传感器信息 | 传感器最全、日志/报表强 | 信息密度过高，像"工具"而非"配件" | 更轻、更快读懂，默认只给 12 项 |
| AIDA64 | 商业全能 | 压力测试 / 报告 / 硬件数据库 | 收费、体积大 | 免费、轻量 |
| MSI Afterburner + RTSS | 游戏内叠加 | OSD、超频、帧率 | 偏游戏场景，桌面常驻弱 | 桌面常驻 + 可换主题 |
| TrafficMonitor | 任务栏网速/CPU | 极轻、任务栏融合 | 无温度、无 GPU 细节 | 全维度信息 |
| LiteMonitor | 轻量桌面面板 | 2 MB、主题化、形态多 | 依赖 WinRing0、无历史、读不到时显示 0 | PawnIO、状态语义、历史与诊断 |

**差异化一句话**：HWiNFO 的准确性 + TrafficMonitor 的轻盈 + 一个真正好看的默认界面。

## 2. 参考项目拆解：借鉴什么，改进什么

### 2.1 LiteMonitor 的能力盘点（来自其 README 与公开评测）

| 维度 | 已实现能力 |
|---|---|
| 监控项 | CPU 使用率/温度（多核平均与峰值）、GPU 使用率/核心温度/显存、内存、磁盘读写、网络上下行、每日流量统计 |
| 形态 | 竖版面板、横条模式、任务栏嵌入、置顶、透明度、圆角、DPI 自适应、多屏 |
| 交互 | 边缘自动隐藏、限制拖出屏幕、鼠标穿透、托盘菜单、拖拽定位 |
| 观感 | 主题 JSON（颜色/字体/间距/圆角）、三色阈值告警、数值平滑动画、智能单位格式化 |
| 工程 | settings.json 实时落盘、多语言、计划任务管理员自启、双源（GitHub + 国内镜像）检查更新、体积约 2 MB |
| 已知代价 | 依赖 **WinRing0** 读取底层传感器，杀软误报需要用户加信任；编译环境为 VS2022 / Rider |

> 说明：上表的"工程实现推断"（.NET + WPF、JSON 主题结构等）来自其公开文档与产物特征，仅用于选型参考，不代表其源码结构。

### 2.2 我们可以直接借鉴的

1. **形态优先**：竖版一块小面板 + 横条模式 + 任务栏模式，比"大而全的主界面"更符合常驻场景。
2. **配置即文件**：`settings.json` + `themes/*.json`，用户可备份、可分享、可手改。
3. **三色阈值**：绿/黄/红直接映射"是否需要注意"，比数字本身更容易被扫视。
4. **管理员计划任务自启**：既解决开机启动，又解决提权后无法开机自启的矛盾。
5. **双源更新**：国内网络环境下，GitHub 直连不可靠，必须有镜像源 + 哈希校验。

### 2.3 必须做得更好的六件事

| # | 参考项目的痛点 | 我们的做法 |
|---|---|---|
| 1 | WinRing0 被 Defender 判为 HackTool | 换 **PawnIO**（开源签名驱动）；驱动按需加载；提供纯用户态"兼容模式" |
| 2 | 读不到的传感器显示 0，误导用户 | 引入 `MetricStatus`（Unavailable/Stale/Error），UI 显示 `--` 并可查看原因 |
| 3 | 只有瞬时值，没有历史 | 环形缓冲 + 可选 SQLite 降采样（1 min 粒度，7 天）与曲线 |
| 4 | 主题/配置无 schema，改坏就崩 | JSON Schema 校验 + 原子写 + 版本迁移 + 坏配置回滚 |
| 5 | 传感器读取失败难定位 | 一键导出诊断包（硬件拓扑、驱动状态、采集耗时、最近 5 分钟采样） |
| 6 | 采集逻辑与 UI 耦合，难测试 | `ISensorProvider` 抽象 + Fake Provider + 渲染快照测试 |

## 3. 技术选型

### 3.1 UI 框架对比（量级估算，M0 实测校准）

| 方案 | 包体 | 常驻内存 | 传感器生态 | UI 表达力 | 跨平台 | 结论 |
|---|---|---|---|---|---|---|
| **WPF / .NET 10** | 2–6 MB（框架依赖）<br>55–70 MB（自包含） | 45–70 MB | ★★★★★ 与 LHM 同栈 | ★★★★ 自绘极强 | Windows | ✅ **推荐** |
| WinUI 3 | 20 MB+（含 Windows App SDK 运行时） | 80–120 MB | ★★★★ | ★★★★★ | Windows | 备选：想要现代控件时 |
| Avalonia 11 | 8–15 MB | 60–90 MB | ★★★★ | ★★★★ | 三平台 | 备选：明确要跨平台时 |
| Tauri 2 + Rust | 6–12 MB | 40–80 MB（共享 WebView2） | ★★★ 需自行 P/Invoke | ★★★★★ | 三平台 | 备选：Web 技术栈团队 |
| Electron | 100 MB+ | 150 MB+ | ★★ | ★★★★★ | 三平台 | ❌ 与"轻量"目标冲突 |
| Qt 6 / C++ | 25–40 MB | 50–80 MB | ★★★★★ | ★★★ | 三平台 | 性能最优但迭代慢 |

**决策：WPF + .NET 10 LTS。**
理由：① 硬件监控的事实标准库 LibreHardwareMonitorLib 是 .NET 库，选它能省掉最贵的一块；② WPF 的 `DrawingContext` 足够做仪表盘级自绘，且不需要额外运行时；③ .NET 10 支持到 2028-11，避免 2026-11 就到期的 .NET 8。

### 3.2 硬件访问层：三条路线

| 路线 | 覆盖 | 成本 | 风险 |
|---|---|---|---|
| A. 全部自研（读 MSR/IO 端口/SMBus/NVMe） | 100% | 极高（每个平台一套） | 高，驱动签名难 |
| B. 全部依赖 LHM | 90% | 低 | GPU 部分不如厂商 SDK 精确；LHM 升级可能破坏 API |
| **C. LHM 负责"主板系"（CPU/主板/风扇/电压/功耗/SMBus），厂商 SDK 负责 GPU，系统 API 负责通用指标** | ~98% | 中 | 需做适配层与降级 |

**决策：C。** 按"数据源"分而治之：

- **CPU/主板/风扇/电压/功耗** → LibreHardwareMonitorLib（PawnIO 驱动）
- **GPU** → NVIDIA **NVML**、AMD **ADLX**、Intel **IGCL**；失败时回退 PDH `GPU Engine` 计数器（只有利用率/显存，没有温度）
- **CPU 利用率/内存/磁盘/网络** → PDH / `NtQuerySystemInformation` / `GlobalMemoryStatusEx` / `GetIfTable2`（零驱动、零管理权）
- **NVMe 温度** → `IOCTL_STORAGE_QUERY_PROPERTY` + `StorageDeviceTemperatureProperty`（零驱动）
- **系统信息** → WMI / SMBIOS / 注册表（只采一次，缓存）

### 3.3 进程模型：先单进程，后拆分

| 阶段 | 模型 | 优点 | 缺点 |
|---|---|---|---|
| M1–M2 | **单进程**：UI 与采集同进程；需要 ring0 时整进程提权（计划任务以最高权限启动） | 简单、快、调试容易 | 提权后 UI 也在高权限，攻击面变大 |
| M3+ | **拆分**：`LiteMon.Agent`（采集服务，LocalSystem）+ `LiteMon.UI`（普通用户），共享内存传快照 | 最小权限原则；采集崩溃不拖垮 UI | 需要 IPC 与生命周期管理 |

**决策**：M1 用单进程把产品跑通；当出现"企业环境不允许 UI 提权"或"需要多用户会话共享采集"的真实需求时，再按 3.3 的第二行拆分。**接口设计从一开始就按可拆分来写**（见 9.2 的 `ISensorProvider` 与 `SnapshotBus`）。

### 3.4 渲染方式：自绘，而不是堆 XAML 控件

| 方式 | 1 s 刷新 12 项 | 60 fps 动画 | 内存 | 结论 |
|---|---|---|---|---|
| XAML + 数据绑定 | 可行但有 GC 抖动 | 依赖动画系统，易掉帧 | 控件树较大 | 不推荐 |
| **自绘（OnRender + FormattedText 缓存）** | 每帧 < 1 ms | 完全可控 | 极小 | ✅ 推荐 |
| Win2D / SkiaSharp | 更强 | 强 | 需额外原生库（+5 MB） | M3 若要做图表再引入 |

关键点：**文本是最大开销**。必须缓存 `FormattedText`（按 文本 + 字体 + 字号 + DPI 作 key），数字变化时只重绘数值区（`InvalidateVisual` 局部脏矩形），而不是整窗重排。

### 3.5 决策记录（ADR 摘要）

| ID | 决策 | 备选 | 后果 |
|---|---|---|---|
| ADR-001 | WPF + .NET 10 | WinUI3 / Avalonia / Tauri | 放弃跨平台与部分现代控件，换取体积与生态 |
| ADR-002 | LHM + 厂商 GPU SDK | 全自研 / 全 LHM | 需要维护适配层；GPU 精度提升 |
| ADR-003 | 每秒不可变快照 | 共享可变状态 / 消息队列 | 每秒 1–4 KB 分配，可忽略；线程安全 |
| ADR-004 | 自绘渲染 | XAML 绑定 | 需要自己实现布局与 DPI，但性能可控 |
| ADR-005 | JSON 配置 + Schema | SQLite / 注册表 | 可读可分享；需要原子写与迁移 |
| ADR-006 | 驱动可选、默认关闭 | 默认加载 | 首次启动无 UAC；温度需用户显式开启 |

### 4.2 模块职责

| 程序集 | 职责 | 依赖 |
|---|---|---|
| `LiteMon.App` | 窗口、托盘、菜单、快捷键、生命周期 | Core / Rendering / Settings |
| `LiteMon.Core` | `MetricId`、`Snapshot`、`SnapshotBus`、调度器、告警引擎 | BCL |
| `LiteMon.Sensors` | 各 `ISensorProvider` 实现（Pdh/Nvml/Adlx/Lhm/Nvme/Net/Wmi） | Core + LHM + 厂商 SDK |
| `LiteMon.Rendering` | 布局引擎、主题解析、`PanelRenderer`、文本缓存、动画 | Core |
| `LiteMon.Settings` | settings.json、迁移、原子写、Schema 校验 | Core |
| `LiteMon.Diagnostics` | 结构化日志、诊断包导出、性能计数器 | Core |

### 4.3 线程模型

| 线程 | 职责 | 优先级 | 说明 |
|---|---|---|---|
| UI 线程 | 渲染、交互 | Normal | 只读快照，**绝不调用**传感器 API |
| 快通道线程 | 1 s：CPU/内存/网络/磁盘 | BelowNormal | 一次循环 ≤ 2 ms |
| 中通道线程 | 2 s：GPU、CPU 温度/频率 | BelowNormal | NVML/LHM 调用可能 3–8 ms |
| 慢通道定时器 | 10 s：设备枚举、SMART、电池、更新检查 | BelowNormal | 走 `Task` + `PeriodicTimer` |
| 文件监视 | 主题/配置热重载 | Normal | 300 ms 去抖 |

**原则**：采集线程永远不碰 UI；UI 线程永远不调用 `Computer.Update()` / `nvmlDeviceGet*`；两者只通过不可变 `Snapshot` 交换。

### 4.4 一次刷新的数据流

```
[1] Scheduler 触发（单调时钟，补偿上次超时）
      ↓
[2] 各 Provider.Poll(writer) → 写入 builder（无锁，仅本线程访问）
      ↓
[3] builder.Build() → Snapshot（不可变，含时间戳与序列号）
      ↓
[4] SnapshotBus.Publish(snapshot) → Volatile.Write(ref _current, snapshot)
      ↓
[5] UI 收到 SnapshotChanged → 计算目标值 → 启动/更新动画 → InvalidateVisual()
      ↓
[6] OnRender：文本缓存命中 → 绘制 12 个数字 + 进度条（< 1 ms）
```

### 4.5 启动与生命周期

```
启动 → 读配置（失败则用默认并备份坏文件）
     → 枚举设备（GPU 型号、网卡、磁盘、主板）
     → 创建 Provider（按可用性裁剪）
     → 首帧：先用缓存的上次快照渲染（避免白屏），再异步首轮采样
     → 事件循环
退出 → 停止调度（Join 超时 2 s）→ 关闭驱动 → 落盘配置 → 释放 SDK
```

## 5. 数据采集设计（核心）

### 5.1 能力矩阵

| 指标 | 首选数据源 | 降级/备选 | 需要 | 档位 | 说明 |
|---|---|---|---|---|---|
| CPU 总利用率 | PDH `\Processor Information(_Total)\% Processor Utility` | `NtQuerySystemInformation` | 无 | 1 s | Utility 在 Win8+ 更贴近任务管理器（含睿频） |
| 每核利用率 | `NtQuerySystemInformation(SystemProcessorPerformanceInformation)` | PDH 每实例 | 无 | 1 s | 单次系统调用取回所有核，开销最低 |
| CPU 频率 | `CallNtPowerInformation(ProcessorInformation)` | LHM（MSR） | 无 / 驱动 | 2 s | 前者为"当前 MHz"，精度略粗 |
| CPU 温度 | **LHM**（Intel DTS / AMD SMU Tctl-Tdie） | WMI `MSAcpi_ThermalZoneTemperature` | 驱动 + 管理员 | 2 s | WMI 台式机普遍不可用，仅作最后兜底 |
| CPU 功耗 | LHM（Intel RAPL / AMD SMU） | — | 驱动 + 管理员 | 2 s | 笔记本可能不暴露 |
| GPU 利用率/温度/显存/功耗/风扇/频率 | **NVML**（NVIDIA）/ **ADLX**（AMD）/ **IGCL**（Intel） | PDH `GPU Engine`（仅利用率） | 无（SDK 随驱动） | 2 s | 混合显卡要枚举全部适配器 |
| 内存使用率 | `GlobalMemoryStatusEx` | PDH `Memory\% Committed Bytes In Use` | 无 | 1 s | 一次 API 返回总量/可用/提交 |
| 内存条信息 | WMI `Win32_PhysicalMemory` + SMBIOS | 注册表 | 无 | 启动一次 | 容量/频率/厂商/槽位 |
| 磁盘吞吐 | PDH `PhysicalDisk(*)\Disk Read/Write Bytes/sec` | `DeviceIoControl` 统计 | 无 | 1 s | 按物理盘聚合，避免分区重复计数 |
| 磁盘温度 | `IOCTL_STORAGE_QUERY_PROPERTY(StorageDeviceTemperatureProperty)` | SMART（ATA，需管理员） | 无 / 管理员 | 10 s | 见 5.4；NVMe 主流可用 |
| 网络速率 | `GetIfTable2`（InOctets/OutOctets 差分） | `NetworkInterface` | 无 | 1 s | 同时可算累计流量；排除虚拟网卡 |
| 风扇转速 | LHM（SuperIO: ITE/Nuvoton/Fintek） | — | 驱动 + 管理员 | 2 s | 笔记本常由 EC 接管，读不到属正常 |
| 电压 | LHM（SuperIO / SMBus） | — | 驱动 + 管理员 | 2 s | 台式机主板才有意义 |
| 电池/电源 | `GetSystemPowerStatus` | WMI `BatteryStatus` | 无 | 10 s | 交流/电池状态影响采样频率 |
| 系统信息 | WMI + SMBIOS（主板/BIOS/CPU 型号/内存总量） | 注册表 | 无 | 启动一次 | 只读一次并缓存 |

> **结论**：不装驱动、不提权即可覆盖 **CPU 利用率、内存、磁盘吞吐、网络、GPU 负载/温度（NVIDIA 走 NVML）、NVMe 温度、系统信息**，这就是"兼容模式"。温度/风扇/电压/功耗是"增强模式"。

### 5.2 驱动与权限策略（本项目最大的风险点）

| 方案 | 覆盖 | 签名 | 杀软态度 | 结论 |
|---|---|---|---|---|
| WinRing0（1.3.0） | 全部 | 有（旧证书） | Defender 报 `HackTool:Win32/Winring0`；部分游戏反作弊拒绝 | ❌ 不用 |
| **PawnIO** | 全部（通过模块化 IO） | 有（持续更新） | 目前较干净 | ✅ 首选 |
| 无驱动 | 80% 指标 | — | 无感 | ✅ 默认档 |
| 厂商 SDK | 仅 GPU | 随驱动 | 无感 | ✅ GPU 专用 |

**加载策略**：

```
首次启动
  ├─ 默认「兼容模式」：不加载驱动，不请求 UAC → 温度显示 "--" + 一键"开启完整监控"按钮
  ├─ 用户点击 → 说明用途（读 MSR/SuperIO，不写硬件）→ 请求提权
  │     ├─ 成功 → 安装/加载 PawnIO → 验证一次读取 → 记住选择
  │     └─ 失败/被杀软拦截 → 回滚到兼容模式 + 给出具体原因与帮助链接
  └─ 企业策略/反作弊场景 → 设置项可强制"永不使用驱动"
```

**注意**：驱动只读、只在本进程生命周期内使用；退出时确保卸载；驱动文件随安装包分发需核对许可证（PawnIO 为开源项目，落地前逐条核对再分发条款）。

**驱动安全边界**（写进代码规范，评审必查）：

- **只做读**：MSR / IO 端口 / SMBus 均只读，不提供任何写接口（写风扇曲线另立项目、单独评估）。
- **白名单**：只允许访问传感器所需的寄存器与端口，禁止通用"读写物理内存"能力。
- **按需加载**：仅在增强模式下加载，退出即卸载；崩溃后下次启动检测残留并清理。
- **最小暴露**：不创建全局命名对象、不驻留后台服务、不接受外部 IPC 指令。
- **可审计**：加载/卸载/失败原因写日志；诊断包包含驱动版本与签名主体。
- **用户可见**：设置页写清"读取哪些硬件、为什么需要管理员、数据不出本机"。

### 5.3 采样调度：多速率 + 无漂移

```csharp
// 单调时钟 + 补偿，避免 Task.Delay 累积漂移
var next = Stopwatch.GetTimestamp();
while (!ct.IsCancellationRequested)
{
    var tickStart = Stopwatch.GetTimestamp();
    PollFastChannel();                       // 目标 ≤ 2 ms
    var snapshot = _builder.Build(tickStart);
    _bus.Publish(snapshot);

    next += Stopwatch.Frequency;             // 固定 1 s 周期
    var remaining = next - Stopwatch.GetTimestamp();
    if (remaining <= 0) { next = Stopwatch.GetTimestamp(); continue; } // 掉帧：跳过错过的周期
    _wake.WaitOne(TimeSpan.FromSeconds(remaining / (double)Stopwatch.Frequency));
}
```

**动态降频**（省电与"不打扰"）：

| 条件 | 行为 |
|---|---|
| 窗口不可见 + 托盘模式 | 快通道降到 5 s，中通道降到 10 s |
| 使用电池 | 全部倍率 ×2 |
| 全屏独占游戏 | 只保留 5 s 一次的 CPU/GPU 概要（可配置为完全暂停） |
| 系统睡眠/会话锁定 | 停止采样；唤醒后重建设备句柄 |
| 传感器连续 N 次失败 | 指数退避到 60 s，并在 UI 标记"传感器离线" |

### 5.4 几个关键实现片段

**① PDH 计数器（一次性初始化，之后每轮只 Collect）**

```csharp
PdhOpenQuery(null, IntPtr.Zero, out var query);
PdhAddEnglishCounter(query, @"\Processor Information(_Total)\% Processor Utility", IntPtr.Zero, out var cpu);
PdhAddEnglishCounter(query, @"\PhysicalDisk(_Total)\Disk Read Bytes/sec", IntPtr.Zero, out var read);
PdhCollectQueryData(query);          // 第一次为基线

// 每轮
PdhCollectQueryData(query);
PdhGetFormattedCounterValue(cpu, PDH_FMT_DOUBLE, out _, out var v);   // v.doubleValue
```

要点：PDH 实例名受本地化影响，**必须用 `PdhAddEnglishCounter`**；计数器句柄只创建一次，不要每轮重建。

**② 每核 CPU 利用率（比 PDH 更快）**

```csharp
// SystemProcessorPerformanceInformation = 8，缓冲区 = 核数 × 48 字节
// 返回每核 IdleTime / KernelTime / UserTime
var busy  = (kernelDelta - idleDelta) + userDelta;
var usage = totalPerCoreDelta == 0 ? 0 : 100.0 * busy / totalPerCoreDelta;
```

**③ NVIDIA GPU（NVML，随驱动安装，无需管理员）**

```csharp
[DllImport("nvml.dll", CallingConvention = CallingConvention.Cdecl)]
static extern int nvmlInit_v2();
[DllImport("nvml.dll", CallingConvention = CallingConvention.Cdecl)]
static extern int nvmlDeviceGetTemperature(nint dev, int sensorType, out uint tempC);
// 依次：nvmlDeviceGetCount_v2 → GetHandleByIndex_v2 → UtilizationRates / MemoryInfo / PowerUsage(mW)
```

**④ NVMe 温度（零驱动、零管理员）**

```csharp
using var h = File.OpenHandle(@"\\.\PhysicalDrive0", FileMode.Open, FileAccess.Read, FileShare.ReadWrite);
// STORAGE_PROPERTY_QUERY { PropertyId = StorageDeviceTemperatureProperty, QueryType = PropertyStandardQuery }
// DeviceIoControl(IOCTL_STORAGE_QUERY_PROPERTY) → STORAGE_TEMPERATURE_DATA_DESCRIPTOR
// 取 HighestTemperature 或第一个 Info[].Temperature（开尔文，减 273.15 得 ℃）
```

> 是否需要管理员取决于打开物理盘句柄的策略，M0 必须在 Win10/Win11 上分别实测，并在失败时静默降级。

**⑤ 网络（`GetIfTable2`，可拿到 64 位累计字节）**

### 5.5 数据模型

```csharp
public enum MetricId : short
{
    CpuLoad = 100, CpuTemp = 101, CpuClock = 102, CpuPower = 103,
    GpuLoad = 200, GpuTemp = 201, GpuMemUsed = 202, GpuMemTotal = 203, GpuPower = 204,
    MemUsedPercent = 300, MemUsedBytes = 301, MemTotalBytes = 302,
    DiskReadBps = 400, DiskWriteBps = 401, DiskTemp = 402,
    NetUpBps = 500, NetDownBps = 501, NetTotalIn = 502, NetTotalOut = 503,
    FanRpm = 600, Voltage = 601,
    BatteryPercent = 700, Uptime = 800,
    Count = 900
}

public enum MetricStatus : byte { Ok, Unavailable, Stale, Error }

public readonly record struct MetricSample(MetricId Id, double Value, MetricStatus Status, long TimestampMs);

public sealed class Snapshot            // 每秒一个，不可变
{
    public required long Sequence { get; init; }
    public required long TimestampMs { get; init; }
    public required IReadOnlyList<MetricSample> Metrics { get; init; }
    public required DeviceSet Devices { get; init; }   // GPU/网卡/磁盘选择
    public MetricSample Get(MetricId id) => Metrics[(int)id];
}
```

**为什么不用可变共享状态**：每秒一次分配（~1–4 KB）对 GC 完全无感，却换来零锁、零撕裂、可回放（历史/测试都复用同一结构）。

### 5.6 失败与降级的语义

| 场景 | 表现 | 用户可见 |
|---|---|---|
| 传感器不存在（虚拟机/笔记本） | `Status = Unavailable` | 该项隐藏或显示 `--`，设置里有"为什么读不到" |
| 读数超时（> 500 ms） | 沿用上一值 + `Stale` | 数字变灰，悬浮提示"数据可能过期" |
| 驱动未加载 | 温度类全部 `Unavailable` | 面板底部提示"完整监控未开启" |
| 设备热插拔（外接显卡/网卡） | 慢通道重新枚举 | 下拉列表自动刷新 |
| Provider 抛异常 | 捕获、计数、退避 | 该项 `--`，日志记录堆栈 |

## 6. 性能设计

### 6.1 预算表

| 项目 | 预算 | 手段 |
|---|---|---|
| 工作集内存 | ≤ 60 MB | 自绘（无控件树）、快照每秒 1 个、图片全部 Freeze() |
| 私有字节 | ≤ 40 MB | 禁用 WPF 的 BitmapCache；不缓存历史点（只用环形缓冲） |
| 空闲 CPU | ≤ 0.3% | 1 Hz 采样 + 无动画时停止重绘（CompositionTarget.Rendering 按需挂载） |
| 单轮采集 | ≤ 2 ms / 8 ms | PDH 句柄复用；LHM 只 Update 已启用的硬件子集 |
| 单帧渲染 | ≤ 1 ms | FormattedText 缓存 + 静态层 DrawingGroup 复用 |
| 启动 | ≤ 800 ms 首帧 | 先渲染缓存快照，再异步首采；不在启动路径做 WMI 枚举 |

### 6.2 十条"别踩"清单

1. 不要在 OnRender 里 new FormattedText（每帧分配 + 文本整形，最贵）。
2. 不要用 XAML 绑定刷新 12 个数字（属性变更通知 + 布局失效，GC 抖动）。
3. 不要每秒重建 PDH 查询或重新 nvmlInit。
4. 不要在 UI 线程调用 Computer.Update()（SuperIO 可能阻塞 10 ms+）。
5. 不要用 Task.Delay(1000) 做周期（累积漂移，长时间后相位乱）。
6. 不要用 DateTime.Now 做间隔计算（NTP 校时会跳变），用 Stopwatch。
7. 不要在窗口隐藏时继续全速采样。
8. 不要为每个传感器建一个 Timer（线程与内核对象爆炸）。
9. 不要把 0 当作"读不到"（必须区分 Unavailable）。
10. 不要在退出时阻塞等待驱动卸载（设 2 s 超时，强制放弃）。

### 8.1 配置（settings.json）

```json
{
  "schemaVersion": 1,
  "appearance": { "theme": "dark-glass", "mode": "portrait", "opacity": 0.92,
                  "scale": 1.0, "alwaysOnTop": true, "clickThrough": false },
  "rows": ["cpu.load", "cpu.temp", "gpu.load", "gpu.temp", "mem.used", "disk.rw", "net.rw"],
  "sampling": { "fastMs": 1000, "mediumMs": 2000, "slowMs": 10000, "pauseWhenHidden": true },
  "devices": { "gpu": "auto", "nic": "auto", "disk": "auto" },
  "alerts": { "cpu.temp": { "high": 85, "hysteresis": 3, "debounceMs": 3000 } },
  "startup": { "enabled": true, "elevated": false },
  "driver": { "mode": "compat" }

```

**写入策略**：500 ms 去抖 → 写 .tmp → File.Replace（首次用 File.Move）→ 保留 .bak。崩溃后启动时若主文件解析失败，自动回滚 .bak 并提示。

**迁移**：schemaVersion 单调递增，逐版本迁移函数链（v1→v2→v3），迁移前先备份；未知的高版本配置拒绝加载而不是瞎猜。

### 8.2 历史与图表（M3）

| 方案 | 体积 | 查询 | 结论 |
|---|---|---|---|
| 内存环形缓冲（1 h，1 s 粒度） | ~2 MB | O(1) | 悬停迷你曲线用这个 |
| SQLite + 降采样 | 每 1000 行 ~50 KB | SQL | 历史页用这个 |

设计：原始 1 s 数据只留 10 分钟；之后按 1 分钟聚合（avg/max/min）保留 7 天；按时间戳建索引并定期 VACUUM。写入用后台线程批量事务（每 10 秒一次），避免每次采样都落盘。

### 8.3 告警

```
value > high + hysteresis 且持续 debounceMs  → 触发
value < high - hysteresis 且持续 debounceMs  → 解除
两次通知间隔 ≥ cooldownMs（默认 5 min）
```

- 通知：托盘气泡（无依赖）+ 可选系统 Toast；声音可关。
- 分级：warn（黄）/ critical（红）；同一时刻最多 1 条聚合通知，避免刷屏。
- 记录：告警事件写入日志与历史表，便于事后复盘（"昨晚 2 点 CPU 到 95 ℃"）。

### 8.4 开机自启

| 方式 | 权限 | 优点 | 缺点 | 用在哪 |
|---|---|---|---|---|
| HKCU Run | 普通 | 简单可靠 | 若程序需提权会弹 UAC | 兼容模式 |
| 计划任务（登录时，最高权限） | 管理员 | 静默提权、可延迟启动 | 需创建任务，用户可见 | 完整模式（推荐） |
| 启动文件夹 | 普通 | 最直观 | 同 Run | 不采用 |

实现：优先用计划任务（Task Scheduler COM 接口，或 schtasks /Create /SC ONLOGON /RL HIGHEST /DELAY 0000:30），任务名 LiteMon；卸载时删除任务。不要写 HKLM Run。

### 8.5 更新

- 清单：版本号 / 下载地址 / SHA-256 / 更新说明，双源（GitHub Releases + 国内镜像），任一可用即可。
- 校验：SHA-256 必须匹配；若安装包已 Authenticode 签名，再校验签名主体。
- 策略：启动后 24 h 静默检查；有新版本只在托盘角标提示，不自动安装（硬件监控的自动重启体验很差）。
- 灰度：清单里带 minOs / channel，避免把不兼容版本推给旧系统。

### 8.6 日志与诊断包

- 结构化日志：Microsoft.Extensions.Logging + 按天滚动文件（保留 7 天，单文件 ≤ 5 MB）。
- 采样慢日志：某轮 > 20 ms 时记录 provider 与耗时（定位是 SuperIO 还是 NVML）。
- **一键诊断包**（zip）：应用版本、OS 版本、CPU/主板/GPU 型号、驱动加载状态、Provider 能力矩阵、最近 5 分钟指标 CSV、脱敏后的配置、最近 200 行日志。用于 issue 复现，避免来回问。

### 9.2 核心接口（可拆分、可测试）

```csharp
public interface ISensorProvider : IAsyncDisposable
{
    string Name { get; }
    ProviderCapabilities Capabilities { get; }      // 支持哪些 MetricId、是否需要提权
    ValueTask InitializeAsync(CancellationToken ct);
    void Poll(IMetricWriter writer, long nowMs);     // 只写，不做 UI、不抛异常
    IReadOnlyList<DeviceInfo> Devices { get; }
}

public interface IMetricWriter
{
    void Write(MetricId id, double value, MetricStatus status = MetricStatus.Ok);
}

public interface ISnapshotSource          // UI 只依赖它
{
    Snapshot Current { get; }
    event EventHandler<Snapshot>? Updated;
}
```

**契约测试**：Poll 不得抛异常、不得耗时超过预算、未支持的指标必须写 Unavailable 而不是不写。所有 Provider 跑同一套 xUnit 测试。

### 9.3 测试策略

| 层级 | 内容 | 工具 |
|---|---|---|
| 单元 | 格式化（B→KB→MB→GB、/s 省略、四舍五入）、滞回、迁移 | xUnit |
| 契约 | 每个 Provider 的初始化/轮询/异常/权限缺失 | xUnit + Fake |
| 渲染 | 100/125/150/200% DPI 下与基准图对比（容差 2%） | RenderTargetBitmap |
| 性能 | Snapshot 构建、渲染单帧 | BenchmarkDotNet |
| 浸泡 | 24 h 连续运行：内存曲线、句柄数、线程数 | 自研探针 + 诊断包 |
| 硬件矩阵 | Intel/AMD CPU、NVIDIA/AMD/Intel GPU、笔记本/迷你主机/虚拟机 | 手动清单 |

**必须在 CI 上跑**：单元 + 契约 + 渲染。**必须在真机上跑**：驱动加载、NVMe 温度权限、多屏 DPI、任务栏嵌入。

## 10. 发布与体积控制

### 10.1 两种发布形态

| 形态 | 体积（估） | 前提 | 适合 |
|---|---|---|---|
| 框架依赖（推荐默认） | 3–6 MB | 用户装 .NET 10 Desktop Runtime（或首启引导安装） | 追求"2 MB 级"体积，如参考项目 |
| 自包含 | 55–70 MB | 无 | 免安装、企业分发、离线机器 |

发布参数要点：

- PublishSingleFile = true，SelfContained = false（框架依赖）
- PublishTrimmed = false —— **WPF 不支持裁剪，也不要试**
- RuntimeIdentifier = win-x64（另出 win-arm64）
- PublishReadyToRun = true（首帧更快，体积 +10 MB；自包含才考虑）

> WPF **不支持** NativeAOT/裁剪；想要 2 MB 就必须框架依赖。这点要在产品页明确写清"需要 .NET 10 Desktop Runtime"，否则用户双击打不开就是差评。

### 10.2 分发渠道

- GitHub Releases：portable zip + MSI（WiX 或 Inno Setup）
- winget（LiteMon.LiteMon）、Microsoft Store（MSIX，可选）
- 国内镜像：对象存储/网盘 + 校验值

### 10.3 签名

- 代码签名证书（OV 即可，EV 可立刻建立 SmartScreen 信誉）
- 驱动文件若随包分发，单独签名并核对许可
- 提交 Defender / 各家杀软误报申诉（驱动类工具必做）

## 12. 风险登记表

| # | 风险 | 概率 | 影响 | 对策 | 预警信号 |
|---|---|---|---|---|---|
| 1 | 驱动被 Defender/杀软拦截 | 高 | 高 | 用 PawnIO；提供无驱动模式；签名 + 误报申诉；安装时说明 | 用户反馈"温度一直是 --" |
| 2 | 笔记本/OEM 读不到温度 | 高 | 中 | 明确标注能力；显示原因；不假装有数据 | 大量 issue "我的 XX 本没有温度" |
| 3 | 反作弊拒绝 ring0 | 中 | 中 | "游戏兼容模式"关闭驱动，仅保留用户态指标 | 玩家反馈游戏闪退/踢出 |
| 4 | 多 GPU/混合显卡识别错 | 中 | 中 | 枚举全部适配器 + 手动选择；记住选择 | 显示的是核显而非独显 |
| 5 | LHM 升级破坏 API | 中 | 中 | 锁版本 + 适配层 + 契约测试；升级前跑硬件矩阵 | 升级后编译或读数异常 |
| 6 | 体积目标与功能冲突 | 中 | 中 | 自绘、框架依赖、按需加载 SDK | 包体逐版膨胀 |
| 7 | 权限提升体验差（每次 UAC） | 中 | 中 | 计划任务静默提权；记住选择 | 用户抱怨每次启动弹窗 |
| 8 | 任务栏嵌入随系统更新失效 | 高 | 低 | 定位实验特性，失败回退横条 | 某次 Windows 更新后消失 |
| 9 | 许可问题（LHM MPL-2.0 / 驱动） | 低 | 高 | 二进制引用 + 保留声明；驱动再分发前逐条核对 | 收到合规问询 |
| 10 | 数值不准引发信任危机 | 中 | 高 | 显示数据源与采样时间；与 HWiNFO 对比校准；说明"厂商读数" | 用户对比后质疑 |

**风险 #1 的兜底方案**：即使 PawnIO 也不可用，产品仍能以"兼容模式"完整交付 80% 价值——这是本方案刻意设计的结构性保险。

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| PDH | Performance Data Helper，Windows 性能计数器 API |
| ring0 | CPU 最高特权级，读 MSR/IO 端口必需，通过内核驱动进入 |
| MSR | Model-Specific Register，CPU 温度/功耗/频率的底层寄存器 |
| SuperIO | 主板上的 I/O 芯片（ITE/Nuvoton/Fintek），负责风扇/电压/温度 |
| NVML | NVIDIA Management Library，驱动自带，用户态调用 |
| DIP | Device Independent Pixel，WPF 的逻辑像素单位 |
