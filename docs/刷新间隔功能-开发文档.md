## 0. 文档说明

### 0.1 这份文档解决什么问题

当前面板**固定每 1 秒**刷新一次数据，用户无法调整。本功能让用户可以在 **1 秒 / 2 秒 / 5 秒 / 10 秒 / 自定义（1–60 秒整数）** 之间切换刷新节奏，并且：

- 切换**立即生效**，不需要重启程序；
- 选择**持久化**，下次启动沿用；
- 面板头部文案同步显示当前节奏；
- 采样成本随间隔自动升降（间隔越大越省电，间隔越小越及时）。

本文档的目标是：**一个不了解本项目的人，照着它可以从零把这个功能写完、测完、打包完**。

## 1. 需求定义

### 1.1 背景

LiteMon 现在的采样节奏写死在代码里：

```
src/LiteMon.Sensors/SamplingService.cs   第 66–74 行：tick % 2 / tick % 10 决定中/慢档
src/LiteMon.App/PanelView.cs             第 202 行：硬编码文案 "每 1 秒刷新"
src/LiteMon.App/PanelWindow.cs           第 42–55 行：右键菜单只有"以管理员身份重启"和"退出"
```

用户场景差异很大：

- **盯温度压测**：希望 1 秒甚至更快，能看出瞬时峰值；
- **挂机看占用**：希望 5–10 秒，省 CPU、省电、不干扰；
- **录屏/演示**：希望 2 秒，数字变化不至于眼花。

### 1.2 用户故事

| 编号 | 作为 | 我想要 | 以便 |
|---|---|---|---|
| US-1 | 性能调优用户 | 右键选 1 秒 / 2 秒 | 压测时看到及时的温度变化 |
| US-2 | 长期挂机用户 | 右键选 5 秒 / 10 秒 | 降低后台 CPU 占用与耗电 |
| US-3 | 特殊需求用户 | 自己输入秒数（如 3 秒、30 秒） | 避开固定档位 |
| US-4 | 所有用户 | 设置重启后还记得 | 不必每次重新选 |

### 1.3 功能需求

| 编号 | 需求 | 验收口径 |
|---|---|---|
| FR-01 | 右键菜单新增"刷新间隔"子菜单 | 菜单里出现 1 秒 / 2 秒 / 5 秒 / 10 秒 / 自定义… |
| FR-02 | 当前生效的档位有勾选标记 | 同一时刻**有且仅有一个**菜单项带勾 |
| FR-03 | 支持自定义输入 | 输入 1–60 的整数被接受；其它输入给出明确错误提示且不关闭对话框 |
| FR-04 | 切换后**立即生效** | 点选后 ≤ 1 个新周期内采样节奏改变，无需重启 |
| FR-05 | 切换后**立即刷新一帧** | 点选后 200 ms 内面板数值更新一次（不用等满新间隔） |
| FR-06 | 头部文案同步 | 显示"每 N 秒刷新"，非预设档位追加"· 自定义" |
| FR-07 | 设置持久化 | 退出重启后沿用上次选择 |
| FR-08 | 设置损坏可恢复 | 配置文件是非法 JSON 时退回默认 1 秒，且把坏文件改名为 `.bad` |

### 1.4 非功能需求

| 编号 | 需求 | 度量方法 |
|---|---|---|
| NFR-01 | 1 秒档单核 CPU 占用 ≤ 3% | `build/diag` 或任务管理器 60 s 平均 |
| NFR-02 | 10 秒档单核 CPU 占用 ≤ 1.5% | 同上 |
| NFR-03 | 切换间隔本身耗时 ≤ 5 ms | `PerfCounters` 打点或秒表 |
| NFR-04 | 工作集不因切换而增长 | 连续切换 50 次，WS 波动 < 10 MB |
| NFR-05 | 采样线程不泄漏 | 退出后 `sampler` 线程结束（`Join(3000)` 成功） |
| NFR-06 | 不影响既有 UI 帧率 | 切换动画仍是 30 fps / 300 ms |

### 1.5 明确不做（v1 范围外）

- ❌ 每个指标单独设间隔（CPU 1 秒、磁盘 10 秒）
- ❌ 亚秒级（`0.5 秒`）——PDH 计数器与 LHM 在亚秒窗口上数值失真，且 CPU 占用翻倍；如未来要支持，需要重新做一轮 M0 式测量
- ❌ 托盘菜单选择间隔（托盘功能本身尚未实现）
- ❌ 间隔变化的托盘通知 / Toast
- ❌ 命令行参数 `--interval`（见第 12 章后续扩展）

### 1.6 一句话验收

> 右键能选 1/2/5/10/自定义，选完立刻变、重启还记得、1 秒档不掉帧、10 秒档不显示 `--`。

### 2.2 采样循环现状

```csharp
// src/LiteMon.Sensors/SamplingService.cs:58-83（现状）
long tick = 0;
while (!_stop.IsSet)
{
    long now = Environment.TickCount64;
    _builder.Begin(now);

    PollByCadence(ProviderCadence.Fast, now);      // 每一拍都采
    if (tick % 2 == 0)  PollByCadence(ProviderCadence.Medium, now);   // 每 2 拍
    if (tick % 10 == 0) PollByCadence(ProviderCadence.Slow, now);     // 每 10 拍

    _bus.Publish(_builder.Build());
    tick++;
    if (_stop.Wait(1000)) break;                   // ← 间隔写死 1000 ms
}
```

三个问题：

1. **间隔写死**：`_stop.Wait(1000)` 无法从外部修改；
2. **档位是"拍数"不是"时间"**：间隔一变，中/慢档的实际周期会被同步放大（例如间隔改 10 秒，慢档变成 100 秒），语义不稳定；
3. **没有"立即重排"能力**：即使能改间隔，线程正阻塞在 `Wait` 里，最长要等满旧间隔才生效。

### 2.3 档位与 Provider 映射（现状）

| 档位 | 周期 | Provider | 说明 |
|---|---|---|---|
| Fast | 1 s | `CpuProvider`、`MemoryProvider`、`NetworkProvider`、`DiskProvider` | 便宜、需要及时 |
| Medium | 2 s | `NvmlProvider`、`LhmProvider` | NVML 调用较贵；LHM 遍历传感器更贵 |
| Slow | 10 s | `UptimeProvider` | 几乎不耗资源 |

> 这个划分是本功能设计的起点：**快档必须有、中档不能低于 2 秒、慢档不能低于 10 秒**（否则 LHM 会显著吃 CPU，M0 报告里有数据）。

### 2.4 关键冲突：12 秒陈旧阈值

```csharp
// src/LiteMon.Core/Metrics/SnapshotBuilder.cs:11-12
/// <summary>超过该时长未更新的 Ok 值会被标记为 Stale（必须大于最慢采样档 10 s）。</summary>
public const long StaleAfterMs = 12_000;
```

`Build()` 会把"超过 12 秒没更新"的 `Ok` 值改成 `Stale`，而 `PanelView.DrawRow` 里：

```csharp
// src/LiteMon.App/PanelView.cs:255-257
var sample = _snapshot.Get(row.Id);
bool valid = sample.Status is MetricStatus.Ok or MetricStatus.Stale;   // Stale 仍显示数字
string text = valid ? Format(row, sample.Value) : "--";
```

好消息：`Stale` **仍然显示数值**，只有 `Unavailable` 才显示 `--`。坏消息：如果某个 Provider 因为间隔被拉长而**跳过**了某轮，超过 12 秒就会被标 `Stale`，语义上会误导未来的健康检查逻辑（例如后续要加"数据过期变灰"）。

更严重的是：**如果用户把间隔设成 20 秒，而 Fast 档每 20 秒才采一次，12 秒阈值会让每个值在 12–20 秒之间反复变成 `Stale`**。当前 UI 看不出来，但这是设计缺陷，必须在本次一并修掉：

> **决策**：陈旧阈值不再写死 12 秒，而是 `max(12 s, 3 × 当前间隔)`。
> 这样任何间隔下都保证"至少容忍 3 个周期"，不会因为用户调大间隔而误判过期。

### 2.7 三条硬约束

1. **分析器是"错误"不是"警告"**：`Directory.Build.props` 里 `TreatWarningsAsErrors=true` + `AnalysisLevel=latest-recommended`。所有新代码必须零警告（CA1305 用 InvariantCulture、CA1031 用异常过滤器、CA2000 及时释放）。
2. **采样线程是背景线程且优先级 BelowNormal**：UI 线程写、采样线程读，只能用 `Volatile`/`Interlocked`，**不要加锁**（锁会让 1 秒档的抖动变大）。
3. **不能引入新依赖**：`LiteMon.Settings` 只用 BCL 的 `System.Text.Json`（已在共享框架里），不新增 NuGet 包——保持便携版体积不变。

## 3. 方案设计

### 3.1 分层与数据流

```
┌──────────────────────────── UI 线程 ────────────────────────────┐
│  PanelWindow（右键菜单）                                         │
│      │ 用户点 1/2/5/10 或自定义                                   │
│      ▼                                                          │
│  App.ApplyInterval(seconds)   ← 唯一的"应用"入口（单一真值来源）    │
│      ├─ RefreshInterval.Normalize()  收敛到 1–60 整数             │
│      ├─ SamplingService.Interval = …  ← 写入（Interlocked）       │
│      ├─ SettingsStore.TrySave()       ← 持久化（失败静默）         │
│      └─ PanelView.SetRefreshInterval() ← 更新头部文案              │
└──────────────────────────────────────────────────────────────────┘
                                │ Volatile 读
┌──────────────────────────── 采样线程 ────────────────────────────┐
│  SamplingService.Run()                                           │
│      每轮读 _intervalMs → 计算 Fast/Medium/Slow 下次到期时间        │
│      → 采样 → Publish(snapshot, staleAfter=max(12s, 3I))         │
│      等待：WaitAny([stop, wake], 到下一次 Fast 的剩余毫秒)          │
└──────────────────────────────────────────────────────────────────┘
```

**为什么是"App 持有真值"而不是每个组件自己存一份**：

- 菜单勾选态、头部文案、采样节奏、配置文件，四处必须一致；
- 只留一个入口 `ApplyInterval`，就不会出现"菜单显示 5 秒但实际 1 秒"的错位；
- 回读时统一走 `RefreshInterval.Normalize`，非法值只能被收敛成合法值，不会扩散。

### 3.2 关键决策

| 编号 | 决策 | 备选方案 | 为什么选它 |
|---|---|---|---|
| **D-01** | 间隔单位：**整数秒**，范围 **[1, 60]** | 小数（0.5 秒起）/ 毫秒 | 亚秒级 PDH 与 LHM 数值失真，且 CPU 翻倍；整数秒覆盖 99% 场景，UI 也最简单 |
| **D-02** | 档位派生：`Fast = I`、`Medium = max(2 s, I)`、`Slow = max(10 s, I)` | 保持 `2I / 10I` 倍数 | 倍数法在 I=10 时把慢档拖到 100 秒，GPU 温度几十秒不更新，观感像卡死；`max` 法保证"**用户设的间隔就是最慢档**" |
| **D-03** | 陈旧阈值：`max(12 s, 3I)` | 保持 12 秒；或 `I + 5 s` | 12 秒在 I>4 秒时必然误判；`3I` 给足 3 个周期的容错，又不会让真正的掉线数据长期伪装有值 |
| **D-04** | 配置位置：**exe 同目录优先**，不可写时退回 `%LOCALAPPDATA%\LiteMon\` | 一律 `%APPDATA%` / 一律 exe 目录 / 注册表 | 便携版主张"拷走文件夹就能带走配置"；但放 Program Files 时目录只读，必须有回退 |
| **D-05** | 生效方式：`Interlocked` 写 + `ManualResetEventSlim` 唤醒 + 调度版本号 | 停止线程再重启 / 让用户重启程序 | 线程重建会丢 Provider 状态（PDH 句柄、NVML 会话）；唤醒只多花几微秒 |
| **D-06** | 单一真值来源：`App.ApplyInterval` | 各组件各自保存 | 避免四处状态不一致（见 3.1 说明） |
| **D-07** | 自定义输入用**模态对话框** | 在面板内联编辑 / InputBox（WinForms） | 内联编辑要改自绘布局与命中测试，成本高；WinForms `InputBox` 会引入 `System.Windows.Forms` 依赖，破坏 WPF 单栈 |

### 3.3 一次切换的完整时序

```
用户右键 → 刷新间隔 → 5 秒
 1. MenuItem.Click 触发 PanelWindow.ApplyInterval(5)
 2. 调用 App 传入的委托 _applyInterval(5.0)
 3. App: normalized = RefreshInterval.Normalize(5) = 5
 4. App: _sampling.Interval = TimeSpan.FromSeconds(5)
        → Interlocked.Exchange(_intervalMs, 5000)
        → _scheduleVersion++，_wake.Set()
 5. App: _settings = _settings with { RefreshIntervalSeconds = 5 }
        → SettingsStore.TrySave(...)  （失败只影响下次启动，不提示）
 6. App: 返回 5.0
 7. PanelWindow: _intervalSeconds = 5.0；_view.SetRefreshInterval(5.0)
        → 头部文案变 "每 5 秒刷新"；InvalidateVisual()
 8. 采样线程：WaitAny 返回 wake → 读到新版本号 → 三个档位到期时间清零
        → 立即采一轮并 Publish（面板 200 ms 内看到新数据）
        → 之后按 5 s / 5 s（≥2 s）/ 10 s（≥10 s）节奏运行
```

### 3.4 间隔取值矩阵（实现后必须与此表一致）

| 用户选择 I | Fast | Medium | Slow | 陈旧阈值 | 1 分钟内的 Fast 采样次数 |
|---|---|---|---|---|---|
| 1 s | 1 s | 2 s | 10 s | 12 s | 60 |
| 2 s | 2 s | 2 s | 10 s | 12 s | 30 |
| 5 s | 5 s | 5 s | 10 s | 15 s | 12 |
| 10 s | 10 s | 10 s | 10 s | 30 s | 6 |
| 60 s | 60 s | 60 s | 60 s | 180 s | 1 |

> 注意 I=2 时 Medium 被"压"到与 Fast 相同（都每拍采），这是 **D-02 的预期行为**：用户要求 2 秒刷新，就不该让 GPU 温度 4 秒才动一次。代价是 NVML/LHM 调用频率翻倍（2 秒一次，与今天的 2 秒档完全相同，不增加成本）。

### 3.5 线程与内存可见性

| 数据 | 写者 | 读者 | 同步手段 |
|---|---|---|---|
| `_intervalMs` | UI 线程 | 采样线程 | `Interlocked.Exchange` / `Volatile.Read` |
| `_scheduleVersion` | UI 线程 | 采样线程 | `Interlocked.Increment` / `Volatile.Read` |
| `_wake` 事件 | UI 线程 `Set` | 采样线程 `WaitAny` | `ManualResetEventSlim`（线程安全的） |
| `AppSettings` | UI 线程 | UI 线程 | 无需同步（只在一个线程用） |
| `Snapshot` | 采样线程 | UI 线程 | 已有的 `Volatile.Write/Read`（不变） |

**禁止**：在采样线程里读 WPF 对象、在 UI 线程里直接调用 Provider。

### 3.6 失败与降级

| 失败点 | 表现 | 处理 |
|---|---|---|
| 配置文件不存在 | 首次启动 | 用默认 1 秒，不创建文件（第一次改动才写） |
| 配置文件非法 JSON | 用户手改坏了 | 改名 `*.bad`，回默认，继续运行 |
| 配置值越界 | 手改 `"refreshIntervalSeconds": 0` | `Normalize` 收敛到 1 |
| 目录只读 | Program Files 部署 | `TrySave` 返回 false，本次不持久化；重启回默认 |
| 采样线程异常 | Provider 抛异常 | 已有逻辑：单 Provider 失败不影响其他、不中断循环（保持） |
| 唤醒事件未触发 | 极端时序 | 最坏情况等满旧周期后自然生效，功能不失效 |

### 4.1 模型

```csharp
// src/LiteMon.Settings/AppSettings.cs（新增）
```

设计要点：

- `Version`：为将来的字段迁移留钩子（当前读到任何版本都按 v1 处理）；

### 4.2 文件格式

路径：`<exe 目录>\LiteMon.settings.json`（回退：`%LOCALAPPDATA%\LiteMon\LiteMon.settings.json`）

```json

  "version": 1,
  "refreshIntervalSeconds": 5
}
```

- 缩进 2 空格、camelCase、UTF-8 无 BOM；
- 只写必要字段，注释不支持（`System.Text.Json` 默认拒绝注释，符合"配置文件不该有注释"的取舍）；
- 未知字段：反序列化时**忽略**（向前兼容），重新保存后自然被丢弃。

### 4.3 校验与兼容规则

| 输入 | 结果 |
|---|---|
| 文件不存在 | `AppSettings.Default`（1 秒） |
| `{}`（空对象） | 属性默认值 → 1 秒 |
| `"refreshIntervalSeconds": 0` | Normalize → 1 |
| `"refreshIntervalSeconds": 999` | Normalize → 60 |
| `"refreshIntervalSeconds": 2.7` | 四舍五入 → 3 |
| `"refreshIntervalSeconds": "abc"` | JSON 反序列化异常 → 回默认 + 隔离坏文件 |
| 非法 JSON | 同上 |
| 多出 `"theme": "dark"` | 忽略，不报错 |

### 4.4 存放位置与原子写

```
启动 → SettingsStore.ResolveDefaultPath()
        ├─ <exe>\LiteMon.settings.json 已存在 → 用它
        ├─ <exe> 目录可写（写一个临时探针文件再删） → 用它
        └─ 否则 → %LOCALAPPDATA%\LiteMon\LiteMon.settings.json
```

保存用"临时文件 + 替换"，避免断电时写出半个 JSON：

### 5.1 新增 `src/LiteMon.Core/Sensors/RefreshInterval.cs`

放在 Core 而不是 Settings，是因为 **采样器（Sensors 项目）和设置（Settings 项目）都要用同一套取值规则**，而 Sensors 不引用 Settings（依赖方向：Core ← Sensors ← App，Core ← Settings ← App）。

```csharp
using System.Globalization;

namespace LiteMon.Core.Sensors;

/// <summary>
/// 刷新间隔的取值域、归一化与展示文案。
/// UI、设置持久化、采样器共用这一份规则，避免三处各写一套边界。
/// </summary>
public static class RefreshInterval
{
    /// <summary>默认间隔（秒）。</summary>
    public const double DefaultSeconds = 1;

    /// <summary>最小间隔（秒）。低于 1 秒时 PDH/LHM 数值失真、CPU 占用翻倍。</summary>
    public const double MinSeconds = 1;

    /// <summary>最大间隔（秒）。再大就没有"实时监控"的意义了。</summary>
    public const double MaxSeconds = 60;

    /// <summary>右键菜单里的预设档位（秒），顺序即菜单顺序。</summary>
    public static readonly IReadOnlyList<double> Presets = [1, 2, 5, 10];

    /// <summary>把任意来源的秒数收敛到 [1, 60] 的整数。</summary>
    public static double Normalize(double seconds)
    {
        if (double.IsNaN(seconds))
        {
            return DefaultSeconds;
        }

        double rounded = Math.Round(seconds, MidpointRounding.AwayFromZero);
        return Math.Clamp(rounded, MinSeconds, MaxSeconds);
    }

    public static bool IsPreset(double seconds) => Presets.Contains(Normalize(seconds));

    /// <summary>解析用户输入：只接受 [1, 60] 的整数（允许 "5" "5.0"，拒绝 "5.5" "abc" "0" "61"）。</summary>
    public static bool TryParse(string? text, out double seconds)
    {
        seconds = 0;
        if (string.IsNullOrWhiteSpace(text))
        {
            return false;
        }

        if (!double.TryParse(text.Trim(), NumberStyles.Float, CultureInfo.InvariantCulture, out double parsed))
        {
            return false;
        }

        if (!double.IsFinite(parsed) || parsed < MinSeconds || parsed > MaxSeconds)
        {
            return false;
        }

        if (parsed != Math.Round(parsed))
        {
            return false;
        }

        seconds = parsed;
        return true;
    }

    /// <summary>面板头部文案，例如 "每 5 秒刷新"、"每 3 秒刷新 · 自定义"。</summary>
    public static string Describe(double seconds)
    {
        double value = Normalize(seconds);
        string text = "每 " + Number(value) + " 秒刷新";
        return IsPreset(value) ? text : text + " · 自定义";
    }

    /// <summary>菜单文案，例如 "每 5 秒"。</summary>
    public static string DescribeShort(double seconds) => "每 " + Number(Normalize(seconds)) + " 秒";

    /// <summary>对话框提示文案。</summary>
    public static string PromptText => "刷新间隔（秒），范围 " + RangeText;

    /// <summary>对话框校验失败文案。</summary>
    public static string ValidationMessage => "请输入 " + RangeText + " 之间的整数秒";

    private static string RangeText
        => string.Create(CultureInfo.InvariantCulture, $"{MinSeconds:0}–{MaxSeconds:0}");

    private static string Number(double seconds)
        => seconds.ToString("0", CultureInfo.InvariantCulture);
}
```

实现要点：

- **所有格式化都走 InvariantCulture**：满足 CA1305，且中文系统与英文系统行为一致；
- `Normalize` 对 `NaN/∞` 返回默认值，杜绝脏数据进入采样线程；
- `TryParse` 用 InvariantCulture 解析，用户在中文输入法下输入全角数字（"５"）会被拒绝并提示，这是有意的（比静默改值更安全）；
- 预设列表放在 Core，UI 只是遍历它——以后要加"15 秒"档，改这一行即可。

```csharp
/// <summary>构建不可变快照：使用默认陈旧阈值 <see cref="StaleAfterMs"/>。</summary>
public Snapshot Build() => Build(StaleAfterMs);

/// <summary>
/// 构建不可变快照：把超过 <paramref name="staleAfterMs"/> 未更新的 Ok 值标为 Stale。
/// 调用方（采样器）会传入 max(默认值, 3 × 刷新间隔)，避免用户把间隔调大后误判过期。
/// </summary>
public Snapshot Build(long staleAfterMs)
{

    {
        throw new ArgumentOutOfRangeException(nameof(staleAfterMs), "陈旧阈值必须为正数。");
    }

    var copy = (MetricSample[])_slots.Clone();

    for (int i = 0; i < copy.Length; i++)

        if (sample.Status == MetricStatus.Ok && _nowMs - sample.TimestampMs > staleAfterMs)

        }
    }

    return new Snapshot(_sequence++, _nowMs, copy);
}
```

### 5.3 重写 `src/LiteMon.Sensors/SamplingService.cs`

这是本次唯一"伤筋动骨"的改动。核心变化：

1. `_stop.Wait(1000)` → `WaitHandle.WaitAny([stop, wake], 到下一次 Fast 的剩余毫秒)`；
2. 拍数计数 → **墙钟到期时间**（`nextFast/nextMedium/nextSlow`）；
3. 新增 `Interval` 属性（`Interlocked` + 版本号），赋值后立即补采一轮；
4. 发布快照时传入动态陈旧阈值。

```csharp
using System.Diagnostics;
using LiteMon.Core.Diagnostics;
using LiteMon.Core.Metrics;
using LiteMon.Core.Sensors;
using LiteMon.Core.Snapshots;

namespace LiteMon.Sensors;

/// <summary>
/// 单采样线程 + 墙钟节拍。刷新间隔可在运行时修改，改动后立即重排并补采一轮。
/// 档位规则：Fast = I；Medium = max(2 s, I)；Slow = max(10 s, I)。
/// 陈旧阈值：max(SnapshotBuilder.StaleAfterMs, 3I)。
/// 单个 Provider 抛异常不影响其他 Provider。
/// </summary>
public sealed class SamplingService : IDisposable
{
    /// <summary>中档周期的下限：LHM/NVML 低于 2 s 会明显吃 CPU。</summary>
    private const int MediumFloorMs = 2_000;

    /// <summary>慢档周期的下限。</summary>
    private const int SlowFloorMs = 10_000;

    /// <summary>单次等待上限，防止时间跳变导致的超长休眠。</summary>
    private const int MaxWaitMs = 60_000;

    private readonly IReadOnlyList<ISensorProvider> _providers;
    private readonly SnapshotBus _bus;
    private readonly SnapshotBuilder _builder = new();
    private readonly ManualResetEventSlim _stop = new(false);
    private readonly ManualResetEventSlim _wake = new(false);
    private readonly WaitHandle[] _waits;

    private Thread? _thread;
    private long _intervalMs = 1_000;
    private long _scheduleVersion;
    private bool _disposed;

    public SamplingService(IReadOnlyList<ISensorProvider> providers, SnapshotBus bus)
    {
        ArgumentNullException.ThrowIfNull(providers);
        ArgumentNullException.ThrowIfNull(bus);

        _providers = providers;
        _bus = bus;
        _waits = [_stop.WaitHandle, _wake.WaitHandle];
    }

    /// <summary>当前刷新间隔（1–60 秒）。赋值后采样线程立即按新节拍重排并补采一轮。</summary>
    public TimeSpan Interval
    {
        get => TimeSpan.FromMilliseconds(Volatile.Read(ref _intervalMs));
        set
        {
            long milliseconds = (long)Math.Round(
                RefreshInterval.Normalize(value.TotalSeconds) * 1000,
                MidpointRounding.AwayFromZero);

            if (Interlocked.Exchange(ref _intervalMs, milliseconds) == milliseconds)
            {
                return;
            }

            // 版本号 + 唤醒：采样线程看到版本变化后会把三个档位的到期时间清零
            Interlocked.Increment(ref _scheduleVersion);
            _wake.Set();
        }
    }

    public void Start()
    {
        if (_thread is not null)
        {
            return;
        }

        _thread = new Thread(Run)
        {
            IsBackground = true,
            Name = "sampler",
            Priority = ThreadPriority.BelowNormal,
        };
        _thread.Start();
    }

    private void Run()
    {
        foreach (var provider in _providers)
        {
            try
            {
                provider.Initialize();
            }
            catch (Exception)
            {
                // 初始化失败 = 该 Provider 不可用，不影响其他
            }
        }

        long nextFast = 0;
        long nextMedium = 0;
        long nextSlow = 0;
        long seenVersion = -1;

        while (!_stop.IsSet)
        {
            long now = Environment.TickCount64;
            long intervalMs = Volatile.Read(ref _intervalMs);
            long version = Volatile.Read(ref _scheduleVersion);

            if (version != seenVersion)
            {
                // 刚改过间隔：三档立即到期，用户不用等满旧周期
                seenVersion = version;
                nextFast = 0;
                nextMedium = 0;
                nextSlow = 0;
            }

            _builder.Begin(now);

            if (now >= nextFast)
            {
                PollByCadence(ProviderCadence.Fast, now);
                nextFast = now + intervalMs;
            }

            if (now >= nextMedium)
            {
                PollByCadence(ProviderCadence.Medium, now);
                nextMedium = now + Math.Max(MediumFloorMs, intervalMs);
            }

            if (now >= nextSlow)
            {
                PollByCadence(ProviderCadence.Slow, now);
                nextSlow = now + Math.Max(SlowFloorMs, intervalMs);
            }

            _bus.Publish(_builder.Build(Math.Max(SnapshotBuilder.StaleAfterMs, intervalMs * 3)));

            int waitMs = (int)Math.Clamp(nextFast - Environment.TickCount64, 1, MaxWaitMs);
            int index = WaitHandle.WaitAny(_waits, waitMs, false);

            if (index == 0)
            {
                break;   // _stop 已置位
            }

            if (index == 1)
            {
                _wake.Reset();   // 被间隔变更唤醒，回到循环顶部重排
            }
        }

        foreach (var provider in _providers)
        {
            try
            {
                provider.Dispose();
            }
            catch (Exception)
            {
                // 退出阶段忽略清理异常
            }
        }
    }

    private void PollByCadence(ProviderCadence cadence, long now)
    {
        foreach (var provider in _providers)
        {
            if (!provider.IsEnabled || provider.Cadence != cadence)
            {
                continue;
            }

            try
            {
                long start = Stopwatch.GetTimestamp();
                provider.Poll(_builder, now);
                PerfCounters.AddPoll(Stopwatch.GetTimestamp() - start);
            }
            catch (Exception)
            {
                // 单轮失败：保持上一轮状态，下一轮继续
            }
        }
    }

    public void Dispose()
    {
        if (_disposed)
        {
            return;
        }

        _disposed = true;
        _stop.Set();
        _thread?.Join(3000);
        _stop.Dispose();
        _wake.Dispose();
    }
}
```

**逐段说明**

| 片段 | 为什么这么写 |
|---|---|
| `WaitHandle.WaitAny(_waits, waitMs, false)` | 同时等待"停止"和"间隔变更"两个信号；返回 0 = 停止，1 = 唤醒，258 = 超时 |
| `nextFast = now + intervalMs` | 用"当前时刻 + 间隔"而不是"上次到期 + 间隔"，避免采样耗时累积漂移 |
| `Math.Clamp(nextFast - TickCount64, 1, MaxWaitMs)` | 到期时间在过去时也要阻塞 1 ms，防止忙等把 CPU 打满；上限防止系统时间跳变后久睡 |
| `seenVersion` 初值 -1 | 保证第一轮一定走"三档到期"分支，启动时立即出数 |
| `_wake.Reset()` 放在循环内 | 必须在消费信号后复位，否则下一轮 WaitAny 会立刻返回形成忙循环 |
| `Math.Max(SnapshotBuilder.StaleAfterMs, intervalMs * 3)` | 见 2.4 节：保证任何间隔下都不误判过期（1 s 档仍为 12 s，10 s 档为 30 s） |

**并发正确性论证**（写进 PR 描述里）：

- UI 线程只做三件事：写 `_intervalMs`、自增版本号、`Set` 唤醒。三者都是线程安全原语。
- 采样线程每轮**先读版本号再读间隔**，两个读之间没有依赖；即使读到"新版本 + 旧间隔"或"旧版本 + 新间隔"，最坏只是晚一拍生效，不会忙等、不会丢数据。
- 不存在锁，不存在 ABA 问题（版本号单调递增）。

#### 5.4.2 `src/LiteMon.Settings/SettingsStore.cs`

```csharp
using System.IO;
using System.Text.Json;
using LiteMon.Core.Sensors;

namespace LiteMon.Settings;

/// <summary>
/// 设置读写。只在 UI 线程使用。
/// 任何失败都不抛异常：读失败回默认值，写失败返回 false。
/// 位置：优先 exe 同目录（便携），不可写时退回 %LOCALAPPDATA%\LiteMon。
/// </summary>
public sealed class SettingsStore
{
    private const string FileName = "LiteMon.settings.json";

    private static readonly JsonSerializerOptions Options = new()
    {
        WriteIndented = true,
        PropertyNamingPolicy = JsonNamingPolicy.CamelCase,
        PropertyNameCaseInsensitive = true,
    };

    private readonly string _path;

    public SettingsStore(string? path = null)
    {
        _path = string.IsNullOrWhiteSpace(path) ? ResolveDefaultPath() : path;
    }

    /// <summary>实际使用的配置文件路径（排障时打印它）。</summary>
    public string Path => _path;

    /// <summary>决定配置写到哪里：exe 目录可写就用它，否则用 LocalAppData。</summary>
    public static string ResolveDefaultPath()
    {
        string appDirectory = GetAppDirectory();
        string besideExe = System.IO.Path.Combine(appDirectory, FileName);

        if (File.Exists(besideExe) || IsDirectoryWritable(appDirectory))
        {
            return besideExe;
        }

        string userDirectory = System.IO.Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
            "LiteMon");
        return System.IO.Path.Combine(userDirectory, FileName);
    }

    /// <summary>读取设置；文件缺失/损坏/越界都返回可用值。</summary>
    public AppSettings Load()
    {
        try
        {
            if (!File.Exists(_path))
            {
                return AppSettings.Default;
            }

            string json = File.ReadAllText(_path);
            AppSettings? settings = JsonSerializer.Deserialize<AppSettings>(json, Options);
            return (settings ?? AppSettings.Default).Normalized();
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException or JsonException or NotSupportedException)
        {
            Quarantine();
            return AppSettings.Default;
        }
    }

    /// <summary>保存设置；失败返回 false（调用方静默处理，不影响采样与显示）。</summary>
    public bool TrySave(AppSettings settings)
    {
        ArgumentNullException.ThrowIfNull(settings);

        try
        {
            string? directory = System.IO.Path.GetDirectoryName(_path);
            if (!string.IsNullOrEmpty(directory))
            {
                Directory.CreateDirectory(directory);
            }

            string json = JsonSerializer.Serialize(settings.Normalized(), Options);
            string temporary = _path + ".tmp";
            File.WriteAllText(temporary, json);
            File.Move(temporary, _path, overwrite: true);
            return true;
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException or NotSupportedException)
        {
            return false;
        }
    }

    private static string GetAppDirectory()
    {
        string? processPath = Environment.ProcessPath;
        if (!string.IsNullOrEmpty(processPath))
        {
            string? directory = System.IO.Path.GetDirectoryName(processPath);
            if (!string.IsNullOrEmpty(directory))
            {
                return directory;
            }
        }

        return AppContext.BaseDirectory;
    }

    private static bool IsDirectoryWritable(string directory)
    {
        try
        {
            string probe = System.IO.Path.Combine(directory, "litemon-write-probe.tmp");
            File.WriteAllText(probe, string.Empty);
            File.Delete(probe);
            return true;
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException or NotSupportedException)
        {
            return false;
        }
    }

    /// <summary>把损坏的配置改名归档，避免每次启动都解析失败。</summary>
    private void Quarantine()
    {
        try
        {
            if (File.Exists(_path))
            {
                File.Move(_path, _path + ".bad", overwrite: true);
            }
        }
        catch (Exception ex) when (ex is IOException or UnauthorizedAccessException or NotSupportedException)
        {
            // 归档失败不影响使用
        }
    }
}
```

**为什么不用 `JsonSerializerContext` 源生成**：当前发布未开启 `PublishTrimmed`（见 `build/publish.ps1`），反射序列化可用且代码更少；若将来开启裁剪，再把 `Options` 换成源生成上下文即可（改动局限在这一个文件）。

**注意**：`System.Text.Json` 对 `0` 与 `0.0` 都能解析到 `double`；`"refreshIntervalSeconds": null` 会得到 `0`，随后被 `Normalized()` 收敛为 1，属于预期。

```csharp
private MenuItem BuildIntervalMenu()
{
    var root = new MenuItem { Header = "刷新间隔" };

    foreach (double preset in RefreshInterval.Presets)
    {
        var item = new MenuItem
        {
            Header = RefreshInterval.DescribeShort(preset),
            IsCheckable = true,
            Tag = preset,
        };
        item.Click += OnPresetClicked;
        _presetItems.Add(item);
        root.Items.Add(item);
    }

    root.Items.Add(new Separator());

    _customItem = new MenuItem { Header = "自定义…", IsCheckable = true };
    _customItem.Click += OnCustomClicked;
    root.Items.Add(_customItem);

    UpdateIntervalChecks();
    return root;
}

private void OnPresetClicked(object sender, RoutedEventArgs e)
{
    if (sender is MenuItem { Tag: double seconds })
    {
        ApplyInterval(seconds);
    }
}

private void OnCustomClicked(object sender, RoutedEventArgs e)
{
    // 菜单关闭动画会抢焦点，延后到下一轮消息泵再弹模态框
    Dispatcher.BeginInvoke(DispatcherPriority.Background, new Action(ShowCustomDialog));
}

private void ShowCustomDialog()
{
    var dialog = new RefreshIntervalDialog(_intervalSeconds) { Owner = this };
    if (dialog.ShowDialog() == true)
    {
        ApplyInterval(dialog.Seconds);
    }
    else
    {
        UpdateIntervalChecks();   // 取消后把勾选态恢复成真实值
    }
}

private void ApplyInterval(double seconds)
{
    double applied = _applyInterval(seconds);

    if (Math.Abs(applied - _intervalSeconds) > 0.001)
    {
        _intervalSeconds = applied;
        _view.SetRefreshInterval(applied);
    }

    UpdateIntervalChecks();
}

private void UpdateIntervalChecks()
{
    foreach (var item in _presetItems)
    {
        item.IsChecked = item.Tag is double value && Math.Abs(value - _intervalSeconds) < 0.001;
    }

    if (_customItem is not null)
    {
        _customItem.IsChecked = !RefreshInterval.IsPreset(_intervalSeconds);
    }
}
```

**为什么用 `Func<double,double>` 而不是 `Action<double>`**：对话框输入 `3.4` 时，真正生效的是 `3`（四舍五入），窗口需要显示"被修正后的值"，否则头部文案与实际节奏不一致。让 App 返回实际值，窗口就永远显示真值。

**菜单勾选态**：WPF 的 `IsCheckable` 只负责画勾，不会自动互斥；必须由 `UpdateIntervalChecks` 手动刷。这是本文件最容易写错的地方——加完功能后检查"连续点 5 次不同档位，是否始终只有一个勾"。

#### 7.2.4 `tests/LiteMon.Sensors.Tests/SamplingServiceTests.cs`（新增）

```csharp
using LiteMon.Core.Metrics;
using LiteMon.Core.Sensors;
using LiteMon.Core.Snapshots;
using LiteMon.Sensors;

namespace LiteMon.Sensors.Tests;

public class SamplingServiceTests
{
    [Fact] // RI-20
    public void IntervalChange_TakesEffectImmediately()
    {
        var bus = new SnapshotBus();
        var fast = new CountingProvider(ProviderCadence.Fast);

        using var service = new SamplingService([fast], bus) { Interval = TimeSpan.FromSeconds(1) };
        service.Start();
        Thread.Sleep(1_600);

        int before = fast.Polls;
        Assert.True(before >= 2, `1 秒档运行 1.6 秒应至少采 2 次，实际 `);

        service.Interval = TimeSpan.FromSeconds(60);
        Thread.Sleep(1_200);

        int delta = fast.Polls - before;
        Assert.True(delta >= 1, "改间隔后应立即补采一轮");
        Assert.True(delta <= 2, "改间隔后不应继续按 1 秒节奏采样");
    }

    [Fact] // RI-21
    public void MediumCadence_NeverSlowerThanInterval()
    {
        var bus = new SnapshotBus();
        var medium = new CountingProvider(ProviderCadence.Medium);

        using var service = new SamplingService([medium], bus) { Interval = TimeSpan.FromSeconds(2) };
        service.Start();
        Thread.Sleep(4_500);

        // 2 秒间隔下：0s / 2s / 4s，容差 2–4 次
        Assert.InRange(medium.Polls, 2, 4);
    }

    private sealed class CountingProvider : ISensorProvider
    {
        private int _polls;

        public CountingProvider(ProviderCadence cadence) => Cadence = cadence;

        public string Name => "counting";

        public ProviderCadence Cadence { get; }

        public ProviderCapabilities Capabilities { get; } = new(new HashSet<MetricId>(), false, false);

        public bool IsEnabled => true;

        public int Polls => Volatile.Read(ref _polls);

        public void Initialize()
        {
        }

        public void Poll(IMetricWriter writer, long nowMs)
        {
            Interlocked.Increment(ref _polls);
            writer.Write(MetricId.CpuLoad, 1);
        }

        public void Dispose()
        {
        }
    }
}
```

- 不用 `Task.Delay` 配 `async void`；

### 7.4 性能回归

**方法**（不要用任务管理器盯 3 秒就下结论）：

```powershell
$env:LITEMON_DIAG = "1"

```

关注字段：`poll`（每轮采样耗时）、`snaps`（5 秒内快照数）、`ws`（工作集）。

| 指标 | 1 秒档门槛 | 10 秒档门槛 |
|---|---|---|
| `snaps`（每 5 秒） | 4–6 | 0–1 |
| `poll` | ≤ 15 ms（p95） | ≤ 15 ms（p95） |
| 进程 CPU（60 s 平均） | ≤ 3% 单核 | ≤ 1.5% 单核 |
| 工作集 | ≤ 220 MB | ≤ 200 MB |

> 基线来自 M0：1 秒档实测 1.6%–2.3%。若超过 3%，先查是否有人把某 Provider 误设成 Fast。

### 7.5 异常注入

| 注入方式 | 期望 |
|---|---|
| 采样中把 `LiteMon.settings.json` 改成只读 | 保存失败但采样继续；无异常日志 |
| 采样中删掉配置文件 | 无影响（只在启动/保存时读） |
| 把系统时间往前调 1 小时 | `WaitAny` 超时上限 60 秒，最多晚 60 秒出数，不卡死 |

## 10. 风险与对策

| 编号 | 风险 | 影响 | 对策 |
|---|---|---|---|
| R-01 | 用户把间隔调到 60 秒后以为程序卡死 | 体验差 | 头部文案明确写"每 60 秒刷新"；后续可加"上次更新于 …" |
| R-02 | 1 秒档在某台机器上 CPU 超标 | 发热/耗电 | 保留 `LITEMON_NO_ANIMATION` 诊断开关；性能不达标时把 Medium 下限从 2 s 提到 3 s（一处常量） |
| R-03 | 配置文件写入失败（Program Files/只读盘） | 设置不持久 | 已设计回退到 `%LOCALAPPDATA%`；仍失败则静默降级 |
| R-04 | 多开实例互相覆盖配置 | 最后写的赢 | 当前无单实例锁（已知遗留）；配置冲突只会丢设置，不崩 |
| R-05 | 唤醒事件丢失导致间隔不生效 | 最长晚 60 秒 | `WaitAny` 有 60 秒上限；下一轮必然重排 |
| R-06 | 动态陈旧阈值被误用（例如未来加"变灰"逻辑） | 语义漂移 | 阈值由采样器统一计算并作为参数传入，不给外部留"默认值"入口 |
| R-07 | 自定义输入框接受全角数字 | 校验失败 | 有明确中文提示，用户可改正；不做自动转换（避免"５"和"5"混用） |
| R-08 | 分析器升级后新规则导致构建失败 | 阻塞 CI | 保持 `TreatWarningsAsErrors`，在 PR 里随规则一起修 |

## 附录 B · 常见问题

**Q：为什么最大只到 60 秒？**
监控面板的价值在"及时"，超过 60 秒就不如直接看任务管理器；另外陈旧阈值会随之放大到 180 秒，语义上已经不算"实时"。

**Q：为什么不能选 0.5 秒？**
PDH 的 `% Processor Utility` 需要 ≥1 秒窗口才稳定；LHM 遍历传感器本身就要几毫秒到十几毫秒，亚秒采样会显著抬高 CPU，且数值抖动没有意义。要做需要先测量，再单独评估。

**Q：选 10 秒后 GPU 温度好像"没反应"？**
这是预期：GPU 温度由 `NvmlProvider`（Medium 档）提供，间隔 10 秒时它也是 10 秒更新一次。如果希望 GPU 更及时，把间隔调小即可。

**Q：配置文件被我改坏了怎么办？**
直接删掉；程序会用默认 1 秒重新开始，并在下次修改时重新生成。损坏的文件会被自动改名成 `*.bad` 留档。

**Q：为什么勾选有时点不动？**
菜单项点击只是"请求变更"，真正生效在 `ApplyInterval`。若 `TrySave` 失败，勾选仍会跟着实际生效值走（这是设计：勾选表示"当前生效"，不是"已保存"）。
