## 0. 文档说明

### 0.1 需求原话拆解

> "设置透明模式……面板透明，字体黑边白体。可以取消进度条用数字代替。可以横向展示省略信息，也可竖向展示详细信息。样式由用户通过右键选择。给予用户一定程度的自定义 UI 空间。"

> "可新增用户可以自己选择显示哪些部件的性能。例如在 CPU 前打钩就显示 CPU，同时在 GPU 前面打钩，就显示 CPU 和 GPU。横版如此，竖版亦如此。"

拆成 6 件事：

| # | 需求 | 本文档对应 |
|---|---|---|
| 1 | 面板半透明，能看见后面的桌面/窗口 | 3.2 透明度管线 |

### 0.2 为什么先出文档

这个功能有一处**技术雷区**（见 3.2.1）：WPF 的"透明窗口"有两种实现，一种会让整个面板退回**软件渲染**，CPU 从 1.6% 飙到 10% 以上——那等于毁掉这个项目的立身之本。所以本文档把"透明度怎么实现"作为**第一个必须验证的里程碑（M0）**，验证不通过就按 3.2.5 的备选降级，而不是硬做。

### 1.4 明确不做

- ❌ 逐"行/单项指标"勾选（例如只显示 CPU 温度、不显示 CPU 使用率）——本轮只到**部件级**，见 11 章问题 2
- ❌ 拖拽调整部件顺序（顺序固定为 CPU → GPU → 内存 → 磁盘 → 网络 → 系统）
- ❌ 点击穿透（鼠标穿过面板点到后面窗口）——会让面板点不到，需额外热键解锁
- ❌ 任意透明度滑块（只给 4 档 + 不透明）
- ❌ 自定义主题色

### 1.5 一句话验收

> 右键能勾选显示哪些部件（至少一项），面板尺寸跟着变；能切成半透明横条、白字黑边、无进度条；重启后全部保留，CPU 不超过 3.5%。

## 2. 现状与约束

### 2.1 当前渲染架构

| 位置 | 现状 |
|---|---|
| `PanelView`（`FrameworkElement` 自绘，约 390 行） | 一个 `OnRender` 画完所有东西：背景、标题、12 行指标、进度条、脚注 |
| 文字 | `FormattedText` + `_textCache`（键 = 文本/字号/粗细，上限 256） |
| 动画 | 数值变化时 30 fps `DispatcherTimer`、300 ms `easeOutCubic` 补间 |
| 布局 | 固定 340×560；`MeasureOverride` 返回常量；行高 = (高 - 头 - 脚 - 组头) / 行数 |
| 进度条 | `DrawRow` 里画 3 DIP 轨道 + 填充（按比例变色） |
| 窗口 | `PanelWindow` 固定 `Width/Height`，`AllowsTransparency=false`（见 2.2） |

### 2.2 关键约束：`AllowsTransparency=true` 会让 WPF 退回软件渲染

这是本项目 **M0 报告**里已经踩过的坑，写在代码注释里：

```csharp
// src/LiteMon.App/PanelWindow.cs:38
// 关闭 AllowsTransparency：分层窗口会让 WPF 退回软件渲染，CPU 会飙升到 10%+
AllowsTransparency = false;
```

含义：**最直观的"透明窗口"写法（`AllowsTransparency=true` + `Background=Transparent`）不可接受**。本功能必须走另一条路（DWM 合成，见 3.2），并且必须实测。

### 2.3 右键菜单现状

`PanelWindow` 构造时一次性建好：`刷新间隔 ▸` → `以管理员身份重启` → `退出`。勾选态由 `UpdateIntervalChecks()` 手动刷新（WPF 的 `IsCheckable` 不会自动互斥）。新增"外观"要沿用这个模式。

### 2.4 设置层现状（可直接扩展）

`AppSettings` 已有 `Version` / `RefreshIntervalSeconds` / `IsPinned` / `WindowLeft` / `WindowTop`，`SettingsStore` 具备原子写、损坏隔离、路径回退。本功能只需**加一个嵌套对象**。

### 2.5 窗口几何与命中区现状

- `PanelWidth=340`、`PanelHeight=560` 是常量，窗口不可缩放；
- 头部命中区：`Y<40`，关闭区 `X>Width-44`，图钉区 `Width-72 < X ≤ Width-44`；
- 图钉、拖动、持久化都依赖 `Width`，所以**改变宽度/高度必须同步命中区**（3.7 会讲）。

## 3. 方案设计

### 3.1 外观模型

新增一个不可变记录（放进 `LiteMon.Core` 的 `Appearance` 命名空间，便于单测）：

```csharp
public enum PanelLayout
{
    Detailed = 0,   // 竖版详细（现版）
    Compact = 1,    // 横版紧凑（单行）
}

[Flags]
public enum PanelGroup
{
    None = 0,
    Cpu = 1,
    Gpu = 2,
    Memory = 4,
    Disk = 8,
    Network = 16,
    System = 32,
    All = Cpu | Gpu | Memory | Disk | Network | System,
}

public sealed record AppearanceSettings
{
    public const int MinOpacity = 45;
    public const int MaxOpacity = 100;
    public const int OpacityStep = 5;

    public PanelLayout Layout { get; init; } = PanelLayout.Detailed;
    public int OpacityPercent { get; init; } = 100;   // 100 = 不透明
    public bool ShowBars { get; init; } = true;

    /// <summary>数值平滑过渡。默认 false：省 CPU（每秒少约 9 帧重绘），数字更锐。</summary>
    public bool SmoothAnimation { get; init; }

    /// <summary>显示哪些部件（默认全选，升级后外观不变）。</summary>
    public PanelGroup VisibleGroups { get; init; } = PanelGroup.All;

    public bool IsTransparent => OpacityPercent < MaxOpacity;

    public bool IsVisible(PanelGroup group) => (VisibleGroups & group) == group;

    public AppearanceSettings Normalized() => this with
    {
        OpacityPercent = NormalizeOpacity(OpacityPercent),
        ShowBars = Layout == PanelLayout.Compact ? false : ShowBars,
        SmoothAnimation = NormalizeOpacity(OpacityPercent) < MaxOpacity ? false : SmoothAnimation,
        VisibleGroups = VisibleGroups == PanelGroup.None ? PanelGroup.All : VisibleGroups & PanelGroup.All,
    };

    private static int NormalizeOpacity(int value)
    {
        int clamped = Math.Clamp(value, MinOpacity, MaxOpacity);
        int snapped = (int)(Math.Round((clamped - MinOpacity) / (double)OpacityStep) * OpacityStep) + MinOpacity;
        return Math.Clamp(snapped, MinOpacity, MaxOpacity);
    }
}
```

> 三条归一化规则：紧凑布局强制无进度条（一行放不下）、可见部件为空时回全选（避免空面板）、未知位被 `& All` 掩掉。
>
> **默认不开启动画**：这是本功能最大的一笔性能取舍——1 s 刷新 + 300 ms 动画 ≈ 每秒 9 帧额外重绘，关掉后每秒只画 1 帧。想要平滑感的用户可在"外观 → 动画"里打开。

### 3.2 透明度方案（本功能的技术核心）

#### 3.2.1 最终结论：必须用分层窗口（M0 推翻了原计划）

| 路线 | 实测结果 |
|---|---|
| **P1** `DWMWA_SYSTEMBACKDROP_TYPE=3` | API 返回 0，但窗口仍不透明 → **无效** |
| **P2** `SetWindowCompositionAttribute(ACRYLIC)` | 只把模糊画在窗口背后，**看不到桌面** → 无效 |
| **P3** 分层窗口 `AllowsTransparency=true` | **唯一真正能透出桌面的方案** ✅ |

原因：非分层窗口没有 alpha 通道，DWM 只能把效果画在窗口背后，窗口本身仍是不透明表面。所以"面板透明、字体不透明"只能由**分层窗口 + 每像素 alpha** 实现。

代价与对策：

| 代价 | 对策 |
|---|---|
| 分层窗口下 WPF 走软件渲染 | **透明时强制关闭动画**（`Normalized()` 写死），每秒只重绘 1 帧，数值不变时完全不重绘 |
| `AllowsTransparency` 只能在创建时设定 | 切透明/不透明时**重建窗口**（见 5.4），位置/固定/间隔/外观全部继承 |
| 软件渲染下动画很贵 | 菜单里"平滑过渡"在透明模式置灰并标注不可用 |

**实测**：45% 透明 + 竖版全选，稳定态 **1.41%**（20 s 平均），不透明 0.94%，只差约 0.5 个百分点。

#### 3.2.2 已废弃方案（仅作记录）

```csharp
internal static class WindowBackdrop
{
    private const int DwmwaSystemBackdropType = 38;
    private const int DwmsbtTransientWindow = 3;   // Acrylic

    [DllImport("dwmapi.dll")]
    private static extern int DwmSetWindowAttribute(IntPtr hwnd, int attribute, ref int value, int size);

    /// <summary>尝试启用亚克力；成功返回 true（失败不抛异常）。</summary>
    public static bool TryEnableAcrylic(Window window)
    {
        IntPtr hwnd = new WindowInteropHelper(window).Handle;
        if (hwnd == IntPtr.Zero)
        {
            return false;
        }

        int value = DwmsbtTransientWindow;
        int hr = DwmSetWindowAttribute(hwnd, DwmwaSystemBackdropType, ref value, sizeof(int));
        return hr == 0;
    }

    /// <summary>让 HwndTarget 背景透明（否则 DWM 背景被不透明底色盖住）。</summary>
    public static void MakeHostTransparent(Window window)
    {
        if (PresentationSource.FromVisual(window) is HwndSource source &&
            source.CompositionTarget is not null)
        {
            source.CompositionTarget.BackgroundColor = Colors.Transparent;
        }
    }
}
```

> ⚠ 上面的 DWM 方案**已废弃**（看不到桌面），保留仅为记录 M0 验证过程；最终实现见 3.2.1 与 5.4。

#### 3.2.3 面板自身的半透明

分层窗口下窗口自身必须完全透明（`Background = Brushes.Transparent`），由 `PanelView` 画带 alpha 的面板底色：

```csharp
// 100% → 0xFF，75% → 0xBF，60% → 0x99，45% → 0x73
byte alpha = (byte)Math.Round(appearance.OpacityPercent * 255 / 100.0);
Background = new SolidColorBrush(Color.FromArgb(alpha, 0x0B, 0x0E, 0x14));
```

配合 DWM 亚克力，观感是"深色毛玻璃"，既透又能看清内容。

#### 3.2.4 不透明时完全走老路

`OpacityPercent == 100` 时：**不调**任何 DWM API、背景 0xFF、关闭描边、动画照常。保证"不改设置就用不到新代码路径"。

#### 3.2.5 不支持 / 异常时的降级

| 情况 | 处理 |
|---|---|
| 远程桌面/虚拟机下分层窗口异常 | 面板仍可显示（可能无透明效果），不崩溃 |
| 用户切透明后系统卡顿 | 菜单切回"不透明"即重建为非分层窗口，恢复硬件渲染 |
| 重建窗口失败 | 回退到原窗口并提示，不影响采样与显示 |
| 用户选透明后把 DWM 服务停了 | 画面退回纯黑不透明，程序不崩；重新选一次即可恢复 |

> **不做**自动切 P3 分层窗口。原因：P3 会毁掉 CPU 指标，而且"透明但卡"比"不透明但流畅"更糟。若你希望极端环境也能透，我可以在 M0 之后单独评估。

#### 3.2.6 必须首先验证（M0）

写代码前先用 `spike/` 探针跑三个数字：

1. P1 能否让桌面透出来（截图判定）；
2. 75% 透明 + 1 s 刷新 + 30 fps 动画时 CPU（20 s 平均）；
3. 关掉动画后的 CPU。

**门槛**：P1 或 P2 任一方案 CPU ≤ 3.5% → 继续；都超标 → 回退到 3.2.5 的降级方案（只做不透明 + 布局/进度条），并重新找你确认。

**M0 实测结论（2026-10-25，`spike/BackdropProbe`）**

| 方案 | 结果 | 20 s 平均 CPU（1 s 刷新、无动画） |
|---|---|---|
| P1 `DWMWA_SYSTEMBACKDROP_TYPE=3` | 返回 0，但窗口仍不透明 → **无效** | 1.35% |
| P2 `SetWindowCompositionAttribute(ACRYLIC)` | **生效**（背后内容透出并虚化） | 1.77% |
| P3 分层窗口 | 未采用（软件渲染风险） | — |

结论：**采用 P2**。窗口全程非分层、硬件渲染；不透明档完全不调用 DWM。

### 3.3 文字"黑边白体"

#### 3.3.1 做法：8 方向 1px 黑晕（不是几何描边）

最初方案是用 `FormattedText.BuildGeometry` + 描边笔（一次绘制黑边+白心）。**实测后否决**：描边会触发轮廓三角化，24 段文字每秒一次就把 CPU 抬到 **3.91%**；换成"黑字偏移 4 次 + 白字覆盖"后降到 **2.34%**（同一配置）。

```csharp
FormattedText shadow = GetText(text, size, bold, ShadowBrush, maxWidth);
dc.DrawText(shadow, new Point(x - 1, y));
dc.DrawText(shadow, new Point(x + 1, y));
dc.DrawText(shadow, new Point(x, y - 1));
dc.DrawText(shadow, new Point(x, y + 1));
dc.DrawText(GetText(text, size, bold, Brushes.White, maxWidth), new Point(x, y));
```

- `ShadowBrush`：近黑 `#F2000000`；8 个方向各偏移 1 DIP；正文白色**完全不透明**；
- 复用 `FormattedText` 缓存（键里**必须包含画刷**，否则黑/白互相污染）；
- 观感：白字带 1px 黑晕，浅色壁纸上依然清晰。

#### 3.3.2 缓存与开销

| 项 | 说明 |
|---|---|
| 建几何成本 | 单条约 0.05–0.2 ms（首次），之后命中缓存 |
| 绘制成本 | 描边比纯填充贵约 30–50%，但只影响文本，不动背景/进度条 |
| 内存 | 12 行 × 2 段文本 ≈ 24 条几何，估计 < 1 MB |

#### 3.3.3 只在透明模式启用

不透明时继续用现在的 `DrawText`（更快）；透明时切 `DrawGeometry`。切换时清空两个缓存（避免混用）。

### 3.4 两种布局

#### 3.4.1 竖版详细（现版，微调）

| 项 | 值 |
|---|---|
| 窗口 | **340 × 动态高度**（公式见 3.4.5） |
| 行 | 每组 1–3 行，随勾选增减 |
| 行高 | **固定 33 DIP**（原 32.67 取整；全选时总高 560 → **564**） |
| 进度条 | 可开关；关闭后行高不变（保持视觉稳定），仅省去 3 DIP 轨道 |
| 组头 | 保留（型号信息） |
| 脚注 | 保留温度来源 |

#### 3.4.2 横版紧凑（新增）

单行条状，每个可见部件一个单元（默认 6 个单元）：

```
┌────────────────────────────────────────────────────────────────────────────┐
│ CPU 23% 76° │ GPU 33% 57° │ 内存 34% │ 磁盘 11.6M/s │ 网络 3.6K/s │ 1d 21:12 │ 📌 × │
└────────────────────────────────────────────────────────────────────────────┘
```

| 单元 | 内容 | 固定宽度（DIP） | 竖版对应 |
|---|---|---|---|
| CPU | 使用率 + 温度 | 112 | 3 行 |
| GPU | 使用率 + 温度 | 112 | 3 行 |
| 内存 | 使用率 | 88 | 1 行 |
| 磁盘 | 读取速率 | 112 | 2 行（省略写入） |
| 网络 | 下行速率 | 112 | 2 行（省略上行） |
| 系统 | 运行时长 | 96 | 1 行 |
| 按钮区 | 图钉 + 关闭 | 72 | 同 |
| 内边距 | 左右各 12 | 24 | — |

**宽度 = 24 + 72 + Σ(可见单元宽度)，高度恒为 44。**

| 勾选 | 宽度 |
|---|---|
| 全选 | **728** |
| CPU + GPU | 320 |
| CPU + GPU + 内存 | 408 |
| 仅 CPU | 208 |

为什么用**固定单元宽度**而不是按内容自适应：数值长度每秒变化（`3.6K/s` ↔ `1.2M/s`），自适应宽度会让窗口"呼吸"，视觉上很糟糕，也会频繁触发窗口重排。

#### 3.4.3 共享与差异

| 项 | 竖版 | 横版 |
|---|---|---|
| 绘制入口 | `DrawDetailed` | `DrawCompact` |
| 进度条 | 可选 | 无 |
| 型号 | 组标题显示 | **不显示**（空间不够，省略） |
| 脚注 | 显示 | 不显示 |
| 动画 | 保留 | **关闭**（见 3.8） |
| 部件勾选 | 生效 | 生效 |
| 头部 | 42 DIP | 无独立头部，图标内联 |

#### 3.4.4 实现方式

不重构整个 `PanelView`（风险大），而是：

```csharp
protected override void OnRender(DrawingContext dc)
{
    if (_appearance.Layout == PanelLayout.Compact)
    {
        DrawCompact(dc);
    }
    else
    {
        DrawDetailed(dc);
    }
}
```

两条路径共用 `GetText` / `Format` / `_snapshot`；差异只在几何。文档不推荐现在抽 `ILayoutRenderer` 接口——两个实现还不足以证明抽象是对的（后续加到 3 种再抽）。

#### 3.4.5 部件可见性（本轮新增）

##### 规则

| 规则 | 说明 |
|---|---|
| 勾选即显示 | 六项独立勾选，可任意组合 |
| **至少一项** | 只剩一项时，那一项的菜单项置灰（无法取消），避免空面板 |
| 顺序固定 | CPU → GPU → 内存 → 磁盘 → 网络 → 系统（不随勾选顺序变化） |
| 两种布局同时生效 | 同一份 `VisibleGroups`：竖版决定显示哪些组，横版决定显示哪些单元 |
| 尺寸联动 | 勾选变化 → 重新计算窗口尺寸 → 收敛位置 → 重绘（见 3.7） |
| 数据照常采集 | 隐藏的部件仍由采样器采集（只是不画），切回来立刻有值，不会出现"刚勾选时是 `--`" |

##### 为什么不做逐行勾选（本轮）

行级勾选需要：行级配置模型、组内行序逻辑、更细的菜单层级（6 组、最多 3 行 = 14 个菜单项），还要定义"只勾 CPU 温度"时组头是否显示、型号是否显示。收益（少两三个数字）与复杂度不成比例，留到下一轮（11 章问题 2）。

### 3.5 进度条开关

- 竖版：`ShowBars=false` 时不画轨道与填充，行高保持不变（否则整表会跳，用户会以为出错）；
- 横版：恒定不画（归一化强制 `false`）；
- 菜单项在横版下置灰（`IsEnabled=false`），并显示"横向紧凑不显示进度条"。

### 3.7 尺寸、命中区、固定、持久化的联动

布局切换会引起窗口尺寸变化，必须成套处理：

| 环节 | 处理 |
|---|---|
| 尺寸 | `PanelMetrics.GetSize(layout, visibleGroups)`：竖版 340×动态高 / 横版 Σ单元+96×44 |
| 命中区 | 关闭区 `X > Width-44`；图钉区 `Width-72 < X ≤ Width-44`；竖版仅 `Y<40`，横版为**整高**（44） |
| 位置 | 尺寸变化后按 `WindowPlacement.Clamp` 重新收敛，保证不出屏 |
| 固定 | 图钉状态与逻辑不变，只是图标坐标随宽度走 |
| 持久化 | 保存 `Layout` / `OpacityPercent` / `ShowBars` / `VisibleGroups`；位置照旧 |
| 动画 | **默认关闭**；只在"平滑过渡"开启且竖版时启动 `_animTimer` |

### 3.8 性能策略

| 场景 | 策略 |
|---|---|
| **默认（任意透明度）** | `SmoothAnimation=false`：数据到达 → 计算 → 画 1 帧，无定时器 |
| 开启平滑 + 不透明·竖版 | 30 fps × 300 ms（沿用现状） |
| 开启平滑 + 透明·竖版 | 降到 15 fps × 300 ms（`LITEMON_TRANSPARENT_FPS` 可调） |
| 任意 + 横版 | 强制关动画（横版是"看数"模式，不做过渡） |
| 数值没变 | 跳过 `InvalidateVisual`（比较待绘制文本），静止时 CPU → 0 |
| 背景 | 半透明背景 + DWM 毛玻璃，不额外做位图缓存 |

**测量方法**：沿用 `LITEMON_DIAG=1` 的 `diag.log`（`poll/render/frames/snaps/ws`），20 s 平均取 CPU。

### 4.1 Schema（v2）

```json
{
  "version": 2,
  "refreshIntervalSeconds": 1,
  "isPinned": true,
  "windowLeft": 1342.7,
  "windowTop": 24,
  "appearance": {
    "layout": "detailed",
    "opacityPercent": 100,
    "showBars": true,
    "smoothAnimation": false,
    "visibleGroups": "cpu, gpu, memory, disk, network, system"
  }
}
```

- `layout` 与 `visibleGroups` 都用字符串（`JsonStringEnumConverter(JsonNamingPolicy.CamelCase)`），手改配置时直观；
- `visibleGroups` 为空串或缺失 → 归一化为 `All`；全选时序列化成字符串 `"all"`（六项都开时比列六个单词更短）；
- 只开部分时写成 `"cpu, gpu"` 这种逗号列表；
- `appearance` 缺失 → 用默认值（老配置天然兼容）；
- `Version` 升到 **2**，但读取时不校验版本（只做归一化），写回时写 2。

### 4.2 归一化规则

| 输入 | 结果 |
|---|---|
| `opacityPercent = 73` | 吸附到 75 |
| `opacityPercent = 10` | 45 |
| `opacityPercent = 300` | 100 |
| `visibleGroups = "none"` / 空串 | `All`（防呆） |
| `visibleGroups` 含未知位（手改） | 与 `All` 求交，保留已知项 |
| `layout = "compact"` + `showBars = true` | 强制 `false` |
| `layout` 未知字符串 | 回 `detailed`（反序列化失败 → 整个配置回默认 + 隔离，与现有策略一致） |

### 4.3 兼容与迁移

| 场景 | 行为 |
|---|---|
| 旧配置（无 `appearance`） | 不透明、竖版、有进度条、**全选** = 与升级前一致 |
| 新配置被旧版本读 | 旧版本忽略 `appearance`，其余字段照常 |
| 用户手改坏 `appearance` | `JsonException` → 整份回默认并隔离为 `.bad`（已有行为） |

### 5.1 `AppearanceSettings.cs`（Core）

```csharp
namespace LiteMon.Core.Appearance;

public enum PanelLayout
{
    Detailed = 0,
    Compact = 1,
}

[Flags]
public enum PanelGroup
{
    None = 0,
    Cpu = 1,
    Gpu = 2,
    Memory = 4,
    Disk = 8,
    Network = 16,
    System = 32,
    All = Cpu | Gpu | Memory | Disk | Network | System,
}

public sealed record AppearanceSettings
{
    public const int MinOpacity = 45;
    public const int MaxOpacity = 100;
    public const int OpacityStep = 5;

    public PanelLayout Layout { get; init; } = PanelLayout.Detailed;

    public int OpacityPercent { get; init; } = MaxOpacity;

    public bool ShowBars { get; init; } = true;

    /// <summary>数值平滑过渡（默认关闭：省 CPU，数字更锐）。</summary>
    public bool SmoothAnimation { get; init; }

    /// <summary>显示哪些部件（位掩码，默认全选）。</summary>
    public PanelGroup VisibleGroups { get; init; } = PanelGroup.All;

    /// <summary>透明度档位（菜单顺序）。</summary>
    public static IReadOnlyList<int> OpacityPresets { get; } = [100, 90, 75, 60, 45];

    public bool IsTransparent => OpacityPercent < MaxOpacity;

    public bool IsVisible(PanelGroup group) => (VisibleGroups & group) == group;

    public AppearanceSettings Normalized()
    {
        int opacity = NormalizeOpacity(OpacityPercent);
        bool bars = Layout == PanelLayout.Compact ? false : ShowBars;
        PanelGroup groups = VisibleGroups & PanelGroup.All;
        if (groups == PanelGroup.None)
        {
            groups = PanelGroup.All;   // 防呆：不允许一个部件都不显示
        }

        return this with { OpacityPercent = opacity, ShowBars = bars, VisibleGroups = groups };
    }

    private static int NormalizeOpacity(int value)
    {
        int clamped = Math.Clamp(value, MinOpacity, MaxOpacity);
        double steps = (clamped - MinOpacity) / (double)OpacityStep;
        int snapped = (int)(Math.Round(steps, MidpointRounding.AwayFromZero) * OpacityStep) + MinOpacity;
        return Math.Clamp(snapped, MinOpacity, MaxOpacity);
    }
}
```

### 5.2 `PanelMetrics.cs`（Core）

把"两种布局的尺寸"变成可测常量（UI 与测试共用）：

```csharp
namespace LiteMon.Core.Appearance;

public static class PanelMetrics
{
    public const double DetailWidth = 340;
    public const double DetailHeader = 42;
    public const double DetailFooter = 24;
    public const double DetailGroupHeader = 17;
    public const double DetailRowHeight = 33;

    public const double CompactHeight = 44;
    public const double CompactPadding = 12;
    public const double CompactButtonZone = 72;

    public const double CompactCellCpu = 112;
    public const double CompactCellGpu = 112;
    public const double CompactCellMemory = 88;
    public const double CompactCellDisk = 112;
    public const double CompactCellNetwork = 112;
    public const double CompactCellSystem = 96;

    /// <summary>绘制顺序（也是菜单顺序）。</summary>
    public static IReadOnlyList<PanelGroup> GroupOrder { get; } =
        [PanelGroup.Cpu, PanelGroup.Gpu, PanelGroup.Memory, PanelGroup.Disk, PanelGroup.Network, PanelGroup.System];

    public static int RowCount(PanelGroup group) => group switch
    {
        PanelGroup.Cpu => 3,
        PanelGroup.Gpu => 3,
        PanelGroup.Memory => 1,
        PanelGroup.Disk => 2,
        PanelGroup.Network => 2,
        PanelGroup.System => 1,
        _ => 0,
    };

    public static double CellWidth(PanelGroup group) => group switch
    {
        PanelGroup.Cpu => CompactCellCpu,
        PanelGroup.Gpu => CompactCellGpu,
        PanelGroup.Memory => CompactCellMemory,
        PanelGroup.Disk => CompactCellDisk,
        PanelGroup.Network => CompactCellNetwork,
        PanelGroup.System => CompactCellSystem,
        _ => 0,
    };

    /// <summary>按布局与可见部件计算窗口尺寸。</summary>
    public static (double Width, double Height) GetSize(PanelLayout layout, PanelGroup visible)
    {
        PanelGroup groups = visible & PanelGroup.All;

        if (layout == PanelLayout.Compact)
        {
            double width = (CompactPadding * 2) + CompactButtonZone;
            foreach (var group in GroupOrder)
            {
                if ((groups & group) == group)
                {
                    width += CellWidth(group);
                }
            }

            return (width, CompactHeight);
        }

        int visibleGroups = 0;
        int rows = 0;
        foreach (var group in GroupOrder)
        {
            if ((groups & group) == group)
            {
                visibleGroups++;
                rows += RowCount(group);
            }
        }

        double height = DetailHeader + DetailFooter + (visibleGroups * DetailGroupHeader) + (rows * DetailRowHeight);
        return (DetailWidth, height);
    }
}
```

> 全选时的宽度推导：112 + 112 + 88 + 112 + 112 + 96 + 72 + 24 = **728**。测试里断言这个等式，改任何单元宽度都会立刻暴露；竖版高度同理断言 564。

### 5.4 `WindowBackdrop.cs`（App）

```csharp
internal static class WindowBackdrop
{
    private const int DwmwaSystemBackdropType = 38;
    private const int DwmsbtTransientWindow = 3;
    private const int AccentEnableAcrylicBlurBehind = 4;

    [DllImport("dwmapi.dll")]
    private static extern int DwmSetWindowAttribute(IntPtr hwnd, int attribute, ref int value, int size);

    [DllImport("user32.dll")]
    private static extern int SetWindowCompositionAttribute(IntPtr hwnd, ref WindowCompositionAttributeData data);

    [StructLayout(LayoutKind.Sequential)]
    private struct AccentPolicy
    {
        public int AccentState;
        public int AccentFlags;
        public int GradientColor;
        public int AnimationId;
    }

    [StructLayout(LayoutKind.Sequential)]
    private struct WindowCompositionAttributeData
    {
        public int Attribute;
        public IntPtr Data;
        public int SizeOfData;
    }

    public static bool TryEnable(Window window, byte alpha)
    {
        ArgumentNullException.ThrowIfNull(window);

        IntPtr hwnd = new WindowInteropHelper(window).Handle;
        if (hwnd == IntPtr.Zero)
        {
            return false;
        }

        // Win11 22H2+：系统背景（亚克力）
        int backdrop = DwmsbtTransientWindow;
        if (DwmSetWindowAttribute(hwnd, DwmwaSystemBackdropType, ref backdrop, sizeof(int)) == 0)
        {
            return true;
        }

        // Win10 1803+：合成属性（亚克力）
        int gradient = (alpha << 24) | 0x000000;   // AABBGGRR，用近黑底
        var policy = new AccentPolicy
        {
            AccentState = AccentEnableAcrylicBlurBehind,
            AccentFlags = 2,
            GradientColor = gradient,
        };

        int size = Marshal.SizeOf<AccentPolicy>();
        IntPtr buffer = Marshal.AllocHGlobal(size);
        try
        {
            Marshal.StructureToPtr(policy, buffer, false);
            var data = new WindowCompositionAttributeData
            {
                Attribute = 19,   // WCA_ACCENT_POLICY
                Data = buffer,
                SizeOfData = size,
            };
            return SetWindowCompositionAttribute(hwnd, ref data) != 0;
        }
        finally
        {
            Marshal.FreeHGlobal(buffer);
        }
    }

    /// <summary>让 HwndTarget 背景透明，DWM 背景才能透出来。</summary>
    public static void MakeHostTransparent(Window window)
    {
        if (PresentationSource.FromVisual(window) is HwndSource source &&
            source.CompositionTarget is not null)
        {
            source.CompositionTarget.BackgroundColor = Colors.Transparent;
        }
    }
}
```

```csharp
    {
        dc.DrawText(GetText(text, size, bold, brush, maxWidth), origin);
```

```csharp

    {
        SnapToTargets();
        if (ContentUnchanged())
        {
```

`ContentUnchanged` 比较"本帧要画的文本集合"与上一帧（标签与数值拼接后的字符串数组），相同则返回 `true`。竖版约 24 个字符串比较，开销可忽略，但能让静止画面 CPU 归零。

`DrawDetailed` = 现有 `OnRender` 的主体（组、行、脚注），只把 `DrawText`/`DrawRow` 换成"描边感知"的版本，并在 `ShowBars` 为 `false` 时跳过轨道绘制；**组循环前先按 `_appearance.IsVisible(group)` 过滤**，行高固定 33、总高由 `PanelMetrics.GetSize` 决定，不再用 `(height-…)/rowCount` 反算。

```csharp
private void ApplyToView(AppearanceSettings appearance)
{
    _appearance = appearance;

    var (width, height) = PanelMetrics.GetSize(appearance.Layout, appearance.VisibleGroups);
    Width = width;
    Height = height;

    var (left, top) = WindowPlacement.Clamp(Left, Top, width, height,
        SystemParameters.VirtualScreenLeft, SystemParameters.VirtualScreenTop,
        SystemParameters.VirtualScreenWidth, SystemParameters.VirtualScreenHeight);
    Left = left;
    Top = top;

    _view.SetAppearance(appearance);
    UpdateAppearanceChecks();
}

private void UpdateAppearanceChecks()
{
    _layoutDetailed!.IsChecked = _appearance.Layout == PanelLayout.Detailed;
    _layoutCompact!.IsChecked = _appearance.Layout == PanelLayout.Compact;

    foreach (var item in _opacityItems)
    {
        item.IsChecked = (int)item.Tag == _appearance.OpacityPercent;
    }

    _barsShow!.IsChecked = _appearance.ShowBars;
    _barsHide!.IsChecked = !_appearance.ShowBars;
    _barsShow.IsEnabled = _appearance.Layout == PanelLayout.Detailed;
    _barsHide.IsEnabled = _appearance.Layout == PanelLayout.Detailed;

    foreach (var (group, item) in _groupItems)
    {
        bool visible = _appearance.IsVisible(group);
        item.IsChecked = visible;

        // 只剩一项时禁止取消，避免空面板
        bool lastOne = visible && _appearance.VisibleGroups == group;
        item.IsEnabled = !lastOne;
        item.Header = lastOne ? GroupLabel(group) + "（至少保留一项）" : GroupLabel(group);
    }
}
```

```csharp
private AppearanceSettings ApplyAppearance(AppearanceSettings appearance)
{
    AppearanceSettings normalized = appearance.Normalized();

    _settings = _settings with { Appearance = normalized };
    _window?.ApplyAppearance(normalized);        // 尺寸 + 视图 + 菜单勾选
    ApplyBackdrop(normalized);                   // 透明度

    if (!_store.TrySave(_settings))
    {
        Debug.WriteLine("LiteMon: 外观设置保存失败");
    }

    return normalized;
}

private void ApplyBackdrop(AppearanceSettings appearance)
{
    if (_window is null)
    {
        return;
    }

    if (!appearance.IsTransparent)
    {
        _window.Background = new SolidColorBrush(Color.FromRgb(0x0B, 0x0E, 0x14));
        return;
    }

    byte alpha = (byte)Math.Round(appearance.OpacityPercent * 255 / 100.0);
    _window.Background = new SolidColorBrush(Color.FromArgb(alpha, 0x0B, 0x0E, 0x14));
    WindowBackdrop.MakeHostTransparent(_window);

    if (!WindowBackdrop.TryEnable(_window, alpha))
    {
        // 不支持：回退不透明，菜单项置灰
        _window.Background = new SolidColorBrush(Color.FromRgb(0x0B, 0x0E, 0x14));
        _window.SetTransparencySupported(false);
    }
}
```

## 11. 决策：一切按"最小资源占用"原则定稿

> 审核意见："这些按照性能消耗最小、最流畅的来做，让该工具不能影响到用户的电脑。"
> 下面 7 条按此原则逐条定稿；每一条都标注了它**省下了什么**。

### 11.1 七条决策

| # | 议题 | 决策 | 省下什么 |
|---|---|---|---|
| 1 | 透明度档位 | **五档：不透明 / 90% / 75% / 60% / 45%**，不做滑块 | 少一个小设置窗；档位有限 → 只有 5 种背景画刷，切换无重排 |
| 2 | 部件粒度 | **只到 6 个部件**，不做行级 | 少一套行级配置模型与 14 项菜单；绘制按组开关，代价 O(1) |
| 3 | 横版单元内容 | CPU(使用率+温度) / GPU(使用率+温度) / 内存 / 磁盘(读) / 网络(下行) / 系统(运行时长)，**一格一个主值** | 每格只格式化 1–2 个数字；不做"读写合计"这类拼接 |
| 4 | 默认勾选 | **全选**（与升级前视觉一致）；想要更省，用户自己取消勾选 | 默认行为可预期；减少绘制由用户按需触发 |
| 5 | 透明模式帧率 | **透明模式完全关闭数值动画**；不透明模式默认也**关闭动画**（菜单可开启"平滑过渡"） | 动画是最大的渲染开销：1 s 刷新 + 300 ms/30 fps ≈ 每秒 9 帧额外绘制；关掉后只在数据到达时画 **1 帧** |
| 6 | 字号/密度 | **不做** | 少一套几何缩放；字号固定 → 文本缓存键更简单 |
| 7 | 点击穿透 | **不做** | 少一条全局热键与解锁 UI |

### 11.2 在此基础上追加的 5 条降耗措施

| 措施 | 说明 | 收益 |
|---|---|---|
| **A. 数据没变就不重绘** | 每次快照到达时，先比较"将要绘制的文本集合"；与上一帧完全相同则跳过 `InvalidateVisual` | 温度/占用稳定时，CPU 接近 0 |
| **B. 透明时才启用 DWM** | 不透明 = 不调用任何 DWM API、不做透明位图 | 不透明用户零额外开销 |
| **C. 动画只在"平滑"模式下存在** | 关闭动画时 `_animTimer` 从不启动 | 无 30 fps 定时器、无逐帧重排 |
| **D. 缓存上限** | 文本 `FormattedText` 与描边 `Geometry` 各 256 条，超出整体清空 | 内存有上界，不会随时长增长 |
| **E. 隐藏部件不绘制** | 数据照采，只是不进绘制循环 | 勾得越少越省（线性） |

### 11.3 性能预算（本功能的硬指标）

| 场景 | 目标 | **实测（测试机型）** | 说明 |
|---|---|---|---|
| 不透明·竖版·全选·无动画（**新默认**） | ≤ 1.8% | **0.94%** | 关动画后比旧版 1.6% 还低 |
| 不透明·竖版·全选·开动画 | ≤ 2.3% | 未测（沿用旧 30 fps 路径） | 与现状持平 |
| 45% 透明·竖版·全选（分层窗口） | ≤ 3.0% | **1.41%** | 软件渲染，但关动画+仅变化时重绘 |
| 45% 透明·横版 | ≤ 2.5% | 1.6%（估） | 面积更小 |
| 75% 透明·横版·仅 CPU+GPU | ≤ 2.0% | 待测 | 单元更少 |

> 若 M0 实测超过上表，先降目标（关动画 → 减帧），仍超标则回退透明（只留不透明 + 布局/勾选），并同步此表。

### 11.4 对既有行为的影响

| 项 | 变化 | 理由 |
|---|---|---|
| 数值动画 | **默认关闭**，菜单"外观 → 动画"可开 | 关掉动画是最大的一笔省电，且数字更"锐" |
| 首次启动 | 与升级前视觉一致（全选、竖版、不透明） | 除动画外不改变观感 |
| 刷新间隔 | 不变（默认 1 s） | 本次不动采样侧 |
