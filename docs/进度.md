### 关键教训

1. `CompositionTarget.Rendering` 的"收敛即停"必须用**时间上限**，不能只看数值差 —— 大数值（字节/秒）按比例逼近，1 秒内根本收敛不了。
2. 网卡枚举比想象中贵得多（28 ms），必须缓存。
3. 分层窗口（`AllowsTransparency=true`）会让 WPF 退回软件渲染，CPU 直接翻倍以上。

## 2026-10-23 · 刷新间隔可调（1/2/5/10/自定义 1–60 秒）

| 项 | 结果 |
|---|---|
| 入口 | 右键菜单「刷新间隔」：每 1/2/5/10 秒 + 自定义…（模态框，1–60 整数秒，非法输入红字提示不关窗） |
| 生效 | 采样器改墙钟调度（原 tick 计数），改间隔后**立即补采一轮**（Interlocked + 版本号 + 唤醒事件） |
| 档位 | Fast = I；Medium = max(2 s, I)；Slow = max(10 s, I)（避免大间隔把慢档拖到 100 秒） |
| 陈旧阈值 | `max(12 s, 3I)`，修掉自定义大间隔被误判 Stale |
| 持久化 | `AppSettings` + `SettingsStore`：优先 exe 目录，不可写回退 `%LOCALAPPDATA%\LiteMon`；临时文件 + 原子替换；损坏隔离为 `.bad` |
| 性能实测 | **1 秒档 1.64%**（20 s 平均，WS 203 MB）；**10 秒档 0.23%**（20 s 平均，WS 215 MB） |
| 验证 | 通过 UI Automation 实测：菜单切 5 秒 → 重启仍为 5 秒；自定义 3 秒头部显示「每 3 秒刷新 · 自定义」；输入 0 被拒并提示；10 秒档全部指标仍有值（无 `--`） |
| 测试 | Core 48 / Sensors 4 / Settings 7 全绿；新增 RI-01~06、SNAP-09/10、RI-10~16、RI-20~23 |
| 文档 | `docs/刷新间隔功能-开发文档.md`（2200 行，含本功能逐文件代码与验收清单） |
| 打包 | `publish.ps1` 打包前清理残留设置文件；`.gitignore` 忽略用户配置 |
